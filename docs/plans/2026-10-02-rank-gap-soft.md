# レベル差制御の作り直し（14人境界の緩和）と重みの総合調整

日付: 2026-10-02 / ブランチ: `claude/rank-gap-soft`（基点 ca0ed7b。試作・計測。本番反映は未実施）

## 背景・方針（ユーザー）

- 優先順位: 1. あまりにレベル差が離れた試合の抑制 > 2. 連続回避（2連続は許容、3連続はまあまあ強く、4連続以上は強く）> 3. 男女。
- 参加回数の公平性（試合数の偏り・待ち）は壊さない。公平性の窓（ハード）は維持。繰り返し回避（variety）も考慮。
- 「14人以下だと全く効かないのは極端」「参加回数も考慮した上で、なるべくレベル差が少なく、かつ繰り返しも考慮したメンバーが選ばれる仕組み」。

## なぜ14人境界があったのか

`WIDE_RANK_SPAN_MIN_ROSTER = 14`（`algorithm.ts`）は 2026-08-05 の plan（`2026-08-05-pairing-goals-and-rewrite.md`）で決めた。
12〜13人2コートは控えが4〜5人しかなく、順位差のハード制約（`ceil(ロースター×2/3)` 以上は違反）を入れると
幅広%は改善する一方で **3-1% が 12人 4.6→11.4%、13人 3.7→8.9% に倍増し、多様性・公平性も揃って悪化**した。
「目的3 ひとつのために他の4指標を落とす」ので小人数はソフトに任せた、という判断。少人数は全体の実力幅が狭く
「大きく離れている」自体が成立しにくい、という理由も併記されている。

今回の再計測でもこれは再現した（下記案 a）。ただし「ソフトが線形で弱い」ため小人数で全く効いていなかったのも事実。

## 試作した案

ハード側とソフト側の2つの手を組み合わせて比較した（`ENGINE=objective CONTINUOUS=1 NOISE=4 ROUNDS=20 SEEDS=100`、
8x1 9x1 10x2 12x2 13x2 14x2 16x2 15x3 19x3 21x3 の10構成平均。基準 = ca0ed7b）。

| 案 | 内容 |
|---|---|
| ca0ed7b | 14人以上のみハード（2/3）。ソフト skillGap は線形（重み1.5）。 |
| a. 全人数にハード | 14人未満にも閾値 `ceil(n×r)` を適用（r = 0.5 / 0.667 / 0.75 / 0.85） |
| b. ハードをやめ凸ソフト | 全人数でハードなし。skillGap を凸形に |
| c. 14人以上ハード維持＋小人数は凸ソフト | 凸形は全人数に掛かるが、14人以上はハードが支配 |

凸形（c の本体）: コート1面あたり `g + slope × max(0, g − knee)²`（g = 順位幅 ÷（ロースター−1））。
さらに g は formRank の幅と登録順位の幅を 1:1 で混ぜる（regMix=0.5）。登録上下%（登録レート上位×下位の同居）を小人数でも抑えるため。

要点:

- **a（小人数にもハード）は不採用**。強さは大きく改善するが、試合数幅が 1.6→2.2、待ちが悪化、3-1 は約2倍、同4人も倍増。2026-08 の判断どおり。
- **b（ハードをやめる）も不採用**。14人以上で幅広% 16.9→28.6 のように強さが大きく悪化する（slope を 8 にしても 14〜21人で ca0ed7b より悪い）。ハードは大人数では必要。
- **c を採用**。ハードは14人以上のまま、小人数は凸ソフトで抑える。ただし凸・regMix とも **単独だと試合数幅と待ちが悪化**する（強さと公平性のトレードオフ）ため、公平性の重みも同時に上げて相殺する（次節）。

### 13人 ↔ 14人の段差

ca0ed7b: 幅広% 39.5（13人）→ 14.4（14人）、登録上下% 53.4 → 19.4。採用案: 32.8 → 13.4、41.1 → 16.2。
**段差は縮まったが残る**（ハードのある/なしの差）。ハードを小人数に広げれば段差は消えるが、上記 a のとおり公平性・男女の代償が大きい
（13人2コートは控えが5人しかなく、ハードで選べる組が枯れる）。「段差なし」は公平性を壊さない範囲では達成できていない。

## 重みの総合調整

凸ソフト（c）を入れると強さは良くなるが公平性が落ちるので、重みを一緒に動かした（SEEDS=100 NOISE=4 の10構成平均で探索）。
主な知見:

- fairness / waiting を 1.5 → 5.0 / 4.0 に上げると試合数幅・待ちが基準以下に戻る（2.5 では 1.59、3 で 1.45、5 で 1.50。3-1 は増える）。
- gender を 1.6 → 3.0 に上げると、凸ソフトで増えた 3-1 を 12.3→10.3 に戻せる（連続への悪影響は小さい。ca0ed7b 時点の「gender を上げると3連続が悪化」は、今回の recency 増強と併用で解消）。
- recency を 2.0 → 5.0（形は据え置き＝2連続目 0.5・3連続目 4.0・4連続目 32 の実効コスト）にすると、variety・fairness を強めたぶん増える3連続が基準に戻る。
- variety 2.6 → 6.0、同4人項 0.5 → 1.5 で同4人% 4.3 → 1.2。強さは悪化するがその分は凸ソフトで取り返せる。
- `rawFloor`（累計の底上げ）は 0.2 → 0.1。0.5 は飽和して悪化（同2人3+% 71）、0 は「同2人4+」は 46.8 まで下がるが試合数幅が 1.75 に悪化。0.1 が折衷。
- competitive（0.5 / 1.6）・skillGap 重み（2.0）の変更は効果が小さい（skillGap 2.0 は強さ微改善・3-1 微悪化）。重みは据え置き（凸形の slope で調整する方が素直）。
- slope: 4 → 6 → 7 → 10 で強さは単調に良くなり、試合数幅・3連続・3-1 が単調に悪化。条件（試合数幅が基準並み）を満たす 6 を採用。

## 採用案

- ハード: 変更なし（14人以上は `ceil(ロースター×2/3)` で B1/B2）。
- ソフト skillGap: 凸形（`RANK_GAP_SOFT_SHAPE = { knee: 0.3, slope: 6, regMix: 0.5 }`、重み 1.5 据え置き）。
- 重み: gender 1.6 → **3.0**、variety 2.6 → **6.0**、fairness 1.5 → **5.0**、waiting 1.5 → **4.0**、recency 2.0 → **5.0**。
- variety 形: `quadWeight` 0.5 → **1.5**、`rawFloor` 0.2 → **0.1**（decay 0.85、power 2.5、scale 6 は据え置き）。

## 前回の未決事項の判断材料

- **同2人の累計4回以上（4+%）**: master 47.2 → ca0ed7b 51.3 → 採用案 50.8。減衰で「当日累計」より「最近」を重視する設計の帰結で、
  採用案でも master には戻らない。`rawFloor` を下げる（0.1 → 0）と 46.8 まで下がるが、試合数幅が 1.75 に悪化する（強さ・公平性が優先なので不採用）。
  累計の底上げを上げる方向（0.3〜0.5）は飽和して逆効果（同2人3+% が 71 まで悪化）。
- **variety の凸版 vs 凹版**: ペア項の指数 1.8 / 2.5 / 3.5 の差は小さい（同2人3+% 66.5 / 66.1 / 66.4、同2人4+% 50.4 / 51.0 / 51.6）。
  凹版（飽和 x/(x+2)）は前 plan で 同2人3+% 71.6 と劣っていた。差は誤差程度なので凸（指数2.5）を維持。繰り返しの改善は形より重み・同4人項の強さが効く。

## 懸念・未決事項

- **男女バランス（3-1%）が 7.6 → 11.2%（+3.6pt）に悪化**。10人2C（16.8→25.9）・15人3C（22.8→27.6）・8人1C（5.3→11.8）が目立つ。
  いずれも少数派が少ない/控えが多く、構造上 2-2 が作りにくい構成。ユーザー方針（男女は優先度が下がった）の範囲として許容したが、
  gender を 3.0 → 3.5 に上げると 3-1 は 8.4% まで戻る代わりに3連続 +0.4pt（n3 実験）。
- **小人数（8人1C・9人1C）の試合数幅が悪化**（1.23 → 1.44 / 1.48 → 1.59）。全体平均は 1.59 → 1.60 で同等、14人以上は改善。
  小人数は選択肢が少なく、凸ソフトの効きが公平性とぶつかる。fairness をさらに上げると試合数幅は戻るが 3-1・同4人が悪化。
- **13人↔14人の段差は縮んだが残る**（上記）。
- 3連続% は 3.0 → 3.1（誤差の範囲）。
- fairness 5.0 が gender 3.0 より強いため、「試合数が1つ遅れている少数派の1人」を 3-1 でも出場させる（`algorithm.test.ts` の該当テストを同数試合の前提に更新）。
- 遅参加・ペア希望あり・ENGINE=legacy は未計測。`slope>0` のため skillGap 項は 1 を超えうる（目的関数値の正規化前提を使うのは `recency` の他のみで影響なし）。
- bench: `SKNEE` / `SSLOPE` / `SREG`（凸形）、`VFAIR` / `VWAIT`（公平性重み）を追加。
