# E-ToMo 進行表への自動チェックイン（毎日 22:00 JST）

## 背景・目的

練習で実際に試合に入った人を、E-ToMo（system.hawai-an.com）のイベント「進行表」で
チェックイン済みにする作業を手動で行っている。セッション（Firestore `sessions/{id}`）の
試合履歴から対象者を割り出し、GitHub Actions で毎日 22:00 JST に自動実行する。

## 対象者

- 対象セッション: `config.practiceStartTime` が実行日（JST）の 0:00〜24:00 にあり、
  `etomoEventId` を持つセッション（オート作成されたもの）。1日に複数あれば全件。
- 対象者: `gameState.matchHistory` の終了済み試合（`finishedAt > 0`）の `teamA`/`teamB`
  に1回以上現れたプレイヤー（ID → `gameState.players` の `name`）。空スロット（空文字）は除外。
- E-ToMo 側の名前（参加予定メンバーのフルネーム）とセッションの `player.name` は
  オート作成・出欠同期で同一表記のため、名前の完全一致（前後空白除去）で突き合わせる。
  一致しない人（アプリで手動追加した人など）はチェックインせず通知に列挙する。

## E-ToMo 側の操作（Playwright）

> **未確定（確認中）**: 進行表でメンバー名をタップすると「出欠実績・会費登録」画面へ進み、
> 当日イベントが複数（楽・単など）あると対象イベントの選択を求められる（ボタン文言は
> イベントタイトル `10/15(木)19:30～21:30@椎名町.楽` 形式）。選択後の登録画面と、
> 下記「1」列チェック＋決定の意味をユーザーに確認中。確定後に本節を書き直す。

1. `ETOMO_URL`（認証付き event_info.php）を開いてセッションを確立
2. イベント詳細 `event_detail.php?...&event_id=<etomoEventId>` を開く
3. 「このイベントの進行表を表示」リンクで進行表へ
4. 進行表のテーブル（列: 通番 / ID / 名前 / 次回予定 / 会費 / 1 / …）と、その下の
   「参加予定メンバー」番号付き一覧（`1 星野真吾` 形式）を読む。
   表の「名前」列はニックネームのことがあるため、**通番 ↔ 参加予定メンバーの番号**で
   フルネームに対応付ける。
5. 対象者の行で見出し「1」列のチェックボックスにチェック（既にチェック済み・
   チェックボックスが無い場合はチェックイン済みとしてスキップ＝冪等）
6. 1件以上チェックしたら「決定」を押す
7. 結果（チェックイン人数・スキップ・未一致）を Discord に通知

セレクタは実 HTML 未確認（スクリーンショットのみ）。構造が想定と違って対応付けが
1件も取れない、列が見つからない等の場合は**何もチェックせず失敗終了**し、Discord に
「進行表の構造を確認してください」と通知する（誤チェックを避ける）。

## 実装

- `src/lib/etomoCheckin.ts` — 純粋関数（対象者の抽出、進行表の通番↔名前対応付け、
  チェック対象行の決定）。ユニットテスト `src/lib/etomoCheckin.test.ts`。
- `scripts/etomo-checkin.ts` — Firestore 読み取り（書き込みなし）＋ Playwright 操作＋通知。
  `DRY_RUN=1` で対象者と予定操作をログ出力するだけ（決定を押さない）。
- `.github/workflows/etomo-checkin.yml` — `cron: '0 13 * * *'`（22:00 JST）＋手動実行
  （`dry_run` 入力）。Playwright の Chromium をインストールして実行。
  公開リポジトリのため、ログに認証付き URL・ページ HTML を出さない。

## 必要な Secrets

既存の `ETOMO_URL`（進行表を開ける管理権限のアカウント。権限不足なら
`ETOMO_CHECKIN_URL` を追加で設定すれば優先）、`DISCORD_WEBHOOK_URL`、`VITE_FIREBASE_*`。
