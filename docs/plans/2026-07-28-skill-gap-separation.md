# 実力が離れすぎた組み合わせを避ける（ハシゴ式の移動幅制限 + 実力差ペナルティ）

2026-07-28

## 背景 / 要望

「3コート・18人程度のとき、最強と最弱は同じコートにあまり入れたくない。
人数やコート数が少ないときはその限りではない」という運用上の意図がある。

現状これを担っているのは `hasIsolatedExtreme`（`algorithm.ts`）だけで、

- 有効なのは **3コート以上**のときだけ（少人数で緩むのは意図どおり）
- ただし弾くのは「**上位1人＋下位3人**」「**下位1人＋上位3人**」のみ。
  **最強1人＋最弱1人＋中位2人は素通り**する

## 計測（実 `assignCourts` を 1 セッション通し・20シード平均・序列ノイズ1.0）

改善前の 18人3コート:

| 指標 | 実測 |
| --- | --- |
| 真の上位3人と下位3人が同じコート | 10.5% |
| 1試合の4人の実力幅（平均） | 9.10 / 17 |
| 同上・ランダムに4人選んだ場合の期待値 | 10.2 / 17 |

**ランダムに選ぶより 11% しか絞れていない**状態だった。

原因は、判定に使う upper/lower が**ハシゴ式（`applyStreakSwaps`）で撹拌された
序列**だったこと。ハシゴ式を通すとグループ内の実力幅が広がる:

| 条件 | 手動序列でグループ分け | ハシゴ式適用後 | 理想 | 全体幅 |
| --- | --- | --- | --- | --- |
| 18人3コート | 5.0 | **10.5** | 5 | 17 |
| 21人3コート | 6.0 | **12.7** | 6 | 20 |
| 24人3コート | 7.0 | **14.4** | 7 | 23 |

つまり「upper グループ」に真の1位と真の12位が同居しうる状態で、その集合に対して
upper/lower 判定をしても実力の分離にならない。

## 変更

### 1. ハシゴ式の移動幅を「元の序列から1グループ分」に制限

`applyStreakSwaps` に、初期序列からのドリフト上限 `maxDrift = stepSize`
（1グループ分）を追加する。

- **回転（コート固定化対策）は維持**: 勝てば上へ、負ければ下へ、2連勝で隣の
  グループへ、という挙動はそのまま
- **積み上がりだけを止める**: 連勝・連敗を重ねても、元の序列から1グループ分より
  遠くへは行かない（＝上位者が下位グループまで沈まない）
- 既存テスト 3 件は「2連勝の正確な着地 index」を検証していたため期待値を更新した。
  上限に当たるので 1 つ手前で止まるが、**上位グループに入るという設計意図は不変**
  （`2026-02-10-court-assignment-fixed.md` の「連勝したら上のコートへ」は保たれる）

### 2. 実力差のソフトペナルティを `selectBestFour` に追加

```
getSkillGapPenalty(4人, 撹拌前の序列, oneGameDelta)
  gap = 4人の順位差（最大−最小）
  allowance = floor(参加人数 / 3)      // 同じグループ相当の幅までは許容
  penalty = oneGameDelta × 2.0 × (gap − allowance) / (人数−1 − allowance)
```

- 判定は**ハシゴ式適用前の序列**（`buildInitialOrder`）で行う。回転はコート割り当て
  側に任せ、実力判定は撹拌前の並びを使う
- **ハード制約ではなくスコア加算**。候補が少ないときは自動的に緩む（今のコードは
  制約を満たせないと借用→フォールバックで結局無視されるため、ソフトの方が構造に合う）
- **`MIN_ROSTER_FOR_SKILL_GAP = 12` 人未満のセッションでは無効**。許容幅も人数比例
  なので、少人数ほど緩くなる（要望どおり）
- 重みは 1.0 / 2.0 / 3.0 を比較して 2.0 を採用（3.0 は分離が頭打ちで公平性だけ悪化）

`hasIsolatedExtreme` は既存のまま残す（ソフトペナルティと二重になるが、既存の
ハード制約を外す必要がないため）。

## 効果（20シード平均・序列ノイズ1.0）

| 条件 | 上位3×下位3 同居 | 実力幅（random比） |
| --- | --- | --- |
| 18人3コート | 10.5% → **4.3%** | 9.10 → **7.96**（random 10.2） |
| 21人3コート | 8.0% → **2.0%** | 10.04 → **8.49**（random 12.0） |
| 24人3コート | 4.7% → **2.0%** | 10.38 → **8.87**（random 13.8） |
| 24人4コート | 7.1% → **1.2%** | 11.03 → **9.10**（random 13.8） |
| 10人2コート | 62.8% → 62.0%（変化なし） | 6.40 → 6.41 |
| 8人2コート | 85.0% → 83.6%（変化なし） | 5.40 → 5.32 |

副作用（回転・公平性）はほぼ無し:

| 指標 | 変更前 | 変更後 |
| --- | --- | --- |
| 1人が使ったコート数（18人3コート） | 2.93 / 3 | 2.96 / 3 |
| 味方になった人数の種類 | 8.0人 | 7.7人 |
| 試合数の最大差 | 2.1 | 2.3 |
| 1回の配置時間 | 3〜5ms | 1〜3ms |

## テスト

`src/lib/algorithm.test.ts`

- 連勝・連敗を重ねても元の序列から1グループ分より遠くへ行かない（上位/下位グループに
  侵入しない）
- 12人で、最上位と最下位が優先度で有利でも同じコートに入らない
- 8人（閾値未満）では同じ条件で両極端が選ばれる（＝少人数では制約しない）
- 実力が近ければ優先度どおりに選ばれる（ペナルティ 0）
- 既存のハシゴ式テスト 3 件は上限に合わせて期待値を更新

## 非対象

- ペア（誰と組むか）の多様性。20人で「一度も味方にならなかった相手」が平均10.7人
  いる件は別途（`selectBestFour` へのパートナー重複ペナルティ / `formTeams` の
  ペア分け選択）
- 3コート以上の逐次配置（1コートずつ貪欲）を全体最適化する話
- 2コート同時配置（`assign2CourtsHolistic`）の確率振り分け。少人数側は要望どおり
  制約しない方針なので変更しない
