# 履歴の「未設定」をタップして本人に割り当て直す（削除メンバーの修復）

2026-08-15

## 背景・課題

オートセッションの出欠同期が試合開始後にメンバーを削除していた事故
（`docs/plans/2026-08-15-auto-session-sync-no-removal-after-start.md` で修正済み）で、
既に開催済みのセッションに壊れた履歴が残っている。

`gameState.players` からプレイヤーが消えても `matchHistory` は変更されないため、
**試合記録そのもの（スコア・時刻・コート・勝敗・出場者の ID）は無事**で、壊れたのは
ID から名前を引く経路だけ。表示は `players.find(...)?.name || '未設定'` の
フォールバックに落ちて「未設定」になる。

当初はワンショットの復旧スクリプトを用意したが、実行に Firebase 認証情報と `tsx` が
必要で、当日その場で直せない。**アプリから直せるほうが運用に合う**ので、履歴画面に
修復導線を持たせてスクリプトは廃止する。

## やること

### 1. 「未設定」だけをタップ可能にする（履歴カード）

- 対象は **orphan ID のみ**: `playerId !== '' && 名簿に居ない`。
  空文字は3人試合の空きスロットで、同じ「未設定」表示でも別物なので**対象外**。
- 権限は `isCreator()`（セッション作成者、または開発モード。既存の勝率表示と同じゲート）。
  権限が無い人にはこれまでどおりただのテキスト。
- 見た目は点線アンダーライン + amber。タップできることが分かり、かつ通常の名前と
  混ざらない程度に控えめにする。

**試合詳細（`/score/:matchId`）ではなく履歴カードに置く理由**: 詳細画面の名前タップは
既に「2人選んでポジションを入れ替える」操作（`ScoreInputPage.handlePlayerTap`）に
使われており、同じジェスチャに別の意味を足すと衝突する。履歴カードは「未設定」に
気づく場所そのものでもある。

### 2. 割り当てモーダル `OrphanPlayerAssignModal`

- 現在の名簿から1人選ぶ。**その試合に既に出ている人は選べない**（二重出場を作らない）。
- 適用範囲を選べる。**既定は「この人の全試合（N件）」**。同じ人が複数試合に出ているのが
  普通で、1試合ずつ直させると取りこぼすため。「この試合だけ」も選べる。
- 名簿に居ない人は先に参加者管理から追加してもらう（モーダルからの新規作成はしない。
  入力口を増やさず既存の名簿 UI に寄せる）。

### 3. mutation `computeAssignOrphanPlayer(state, orphanId, newPlayerId, matchId?)`

**正しい記録を書き換えられないことを、UI ではなく mutation で担保する**:

- `orphanId` が現在の名簿に居るなら **no-op**（＝「今いるメンバーの試合を別人に
  差し替える」経路は存在しない）。
- `newPlayerId` が名簿に居ないなら no-op。
- 置換すると同じ試合に `newPlayerId` が2回現れる試合はスキップ。

差し替え後は既存の `recomputePlayerMatchStats` で `gamesPlayed` / `lastPlayedAt` を
履歴と整合させる（履歴削除で使っている関数をそのまま再利用）。勝率・成績サマリ・
パフォーマンスレート・履歴フィルタはすべて `matchHistory` からの導出なので自動で追従する。

`matchId` 未指定（全試合）のときはコート・予約に残った参照も差し替える。
単一試合の修正ではその試合の記録だけを直したいので、コート・予約には触れない。

## 非対象

- **正しく設定済みのスロットの編集**。誤タップで正しい記録を壊すリスクのほうが大きく、
  復旧という目的には未設定限定で足りる。必要になったら別 plan で。
- 空きスロット（3人試合の `''`）への割り当て。試合構成の変更であって修復ではない。
- 名寄せ（表記揺れの統合）そのもの。
- **GAS へアップロード済みの試合結果**。`docs/webhook.js` は matchId で重複排除する
  ため、修復後に再送しても当日結果シートの行は更新されない。シート側は手で直す。

## テスト

`src/services/sessionMutations.test.ts`:

- `isOrphanPlayerId`: 名簿に居ない / 居る / 空文字
- `countOrphanMatches`: 出場試合数 / 空文字は 0
- `computeAssignOrphanPlayer`:
  - 全試合の差し替えと `gamesPlayed` / `lastPlayedAt` の再計算
  - `matchId` 指定で1試合だけ
  - 名簿に居るプレイヤーは no-op（正しい記録は書き換えられない）
  - 割り当て先が名簿に居なければ no-op
  - 同じ試合に既に出ている人へは寄せない
  - 全試合モードのみコート・予約も差し替える
  - スコア・時刻・勝敗は変更しない
