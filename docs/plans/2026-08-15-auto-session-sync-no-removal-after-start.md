# オートセッション同期: 開始後はメンバーを削除しない

2026-08-15

## 背景・課題

自動セッション作成の再実行（`scripts/auto-create-session.ts` の `syncSessionRoster`）は、
E-ToMo の最新出席者リストとセッションの `gameState.players` を突き合わせ、
**差分の削除まで実行**していた（`docs/plans/2026-07-15-auto-session-etomo-sync.md`）。

これが練習当日、**試合開始後**に再実行されると実害が出る。

1. **ニックネームの表記揺れ**。当日その場で参加が決まった人などを管理者がアプリ側から
   手動追加すると、E-ToMo の登録名と表記が揃わないことがある
   （例: アプリ「ゆーた」/ E-ToMo「ゆーた(たっちゃん)」）。名前の集合差分では
   「表記が違うだけの同一人物」と「本当に欠席した人」を区別できないため、
   同期が手動追加したメンバーを消してしまう。
2. **試合結果が既にある**。試合に出た人を消すと `matchHistory` には ID だけが残り、
   名前を引けなくなる。履歴・成績サマリ・会計の整合が崩れ、しかも自動では戻せない。

削除は取り返しがつかない一方、削除を見送って残る害は「欠席者が待機列に居続ける」
だけで、アプリの名簿編集から手で消せる。**非対称なので安全側に倒す。**

## やること

### 1. セッション開始判定 `hasSessionStarted(state)` を追加

以下のいずれかで「開始済み」とみなす:

- `matchHistory` が空でない
- いずれかのコートにメンバーが乗っている（`teamA`/`teamB` に非空 ID / `isPlaying` /
  タップ交換の `restingPlayerIds`）

初回配置直後は履歴がまだ空なので、履歴の有無だけでは足りない（配置済みなら開始済み）。

### 2. `computeRosterSync` は開始後に削除しない

- 開始済み → **削除対象を全員据え置き**（`skippedRemovals` として返す）。
- 開始前でも、試合結果を持つプレイヤー（`gamesPlayed > 0` または `matchHistory` に
  ID が載っている）は同じ理由で保護する。
- **追加（新規出席登録）は開始後も従来どおり反映する。** 当日合流を取り込むのが
  再実行の主目的で、追加は破壊的でない。
- レート同期（`syncExistingRatings`）の条件も `matchHistory` 非空から
  `hasSessionStarted` に統一する。オプション引数は廃止し、判定を state から
  導出する1本に寄せる（呼び出し側で条件がずれる余地を無くす）。

戻り値に `skippedRemovals: string[]` と `sessionStarted: boolean` を追加する。
Firestore への書き込み条件（追加/削除/レート更新のいずれかがある）は据え置きなので、
**見送りだけのときは書き込みが発生しない**。

コート上の参照掃除（`teamA`/`teamB` の空文字化、`restingPlayerIds` の除外）は
「開始前は誰もコートに乗っていない」ため実際には効かなくなるが、保護条件が将来
変わったときに宙に浮いた ID を残さないための不変条件として残す。

### 3. Discord 通知に「削除を見送り」を出す

削除を見送った名前と理由（試合開始後 / 試合結果あり）を列挙し、
「本当に欠席の場合はアプリの名簿編集から削除してください」と促す。
見送りのみ（他に変更なし）でも「変更なし」ではなくこの通知を出す。

## 非対象

- 表記揺れの**名寄せ**（正規化・別名テーブル）。今回は「消さない」までで、
  同一人物の統合はしない（結果として E-ToMo 表記の別プレイヤーが追加される）。
- 支払い済み（`paymentTimestamp`）など会計データを持つプレイヤーの保護。
  実運用では会計対応済み＝開始後なので上記の保護で覆われる。
- 開始後に欠席した人の自動削除・自動休憩化。管理者の手動操作に委ねる。

## テスト

`scripts/auto-create-session.test.ts`:

- `hasSessionStarted`: 履歴 / コート配置 / `isPlaying` / `restingPlayerIds` / 未開始
- `computeRosterSync`:
  - コート配置済み・履歴ありで削除されず `skippedRemovals` に入る
  - 表記揺れシナリオ（手動追加の「ゆーた」が残り、E-ToMo 表記は追加される）
  - 開始前でも `gamesPlayed > 0` は保護し、それ以外は従来どおり削除される
  - 開始後はレートを更新しない
