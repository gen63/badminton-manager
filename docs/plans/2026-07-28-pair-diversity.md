# ペア・対戦相手の多様性を上げる

2026-07-28

## 背景

ダブルス配置で多様性を見ていたのは次の 2 つだけで、どちらも「4人の集合」単位だった。

- `hasSimilarRecentMatch`: 直近3試合と4人中3人以上重複したら禁止
- `getComboRepeatPenalty`: 同じ4人組が3回目以降ならペナルティ

**「誰と組んだか」「誰と当たったか」は一切カウントしていない**。`formTeams` も序列順に
「1位+4位 vs 2位+3位」固定なので、同じ4人なら常に同じペア分けになる。

（設定の `prioritizeDiversity` は UI の「まだ配置しない方がいい」警告
`shouldBlockForDiversity` 専用で、組み合わせ算出には流れていない）

## 指標の取り方に注意

素朴に「一度も味方にならなかった人数」を測ると 20人4コート60試合で 10.7人/19人となるが、
**この大半は実力帯が離れていて会わない相手**で、実力差の分離
（`2026-07-28-skill-gap-separation.md`）の意図どおりの結果。薄まった指標では改善が見えない。

そこで **「序列差が1グループ幅（人数の1/3）以内の相手との未共演率」** を主指標にした。

## 変更

### 1. `formTeams` のペア分け選択

`matchHistory` を任意引数で追加（省略時は従来どおり 1+4 vs 2+3）。3通りのペア分け
（1+4/2+3、1+3/2+4、1+2/3+4）から、

- 序列位置の合計差（バランス指標）が最良ペア分けより `人数の1/3` を超えて悪化しない候補に絞り
- その中で過去のパートナー/対戦相手回数の合計が最小のものを選ぶ

2M+2F の MIX 優先ロジックは従来どおり優先する。

### 2. `selectBestFour` にペア重複ペナルティ

`buildPairHistoryCounts()` で履歴を1回だけ走査し、全ペアの「パートナーだった回数」
「対戦相手だった回数」を集計（n⁴ ループの外なので性能劣化なし）。4人から作れる全6ペア分の
合計に重みを掛けてスコアに加算する。

- `PARTNER_REPEAT_WEIGHT = 0.1` / `OPPONENT_REPEAT_WEIGHT = 0.05`（`oneGameDelta` 単位）
- `PAIR_REPEAT_PENALTY_CAP` で上限を設ける（当初 0.3。レビュー後 0.2 に調整。
  詳細は `2026-07-28-mix-preference.md`）。6ペア合計に掛けるため終盤に青天井で
  膨らみ、実力差ペナルティ（最大 2.0）と competing する規模になるのを防ぐ

## 効果（20シード平均、20人4コート60試合）

| 指標 | 変更前 | `formTeams` のみ | 採用（両方 + cap） |
| --- | --- | --- | --- |
| **実力が近い相手との未共演率** | 42% | 33% | **31%** |
| 実力が離れた相手との未共演率 | 71% | 73% | 72%（意図どおり不変） |

実力分離・回転・公平性への影響（80シード平均で測定。20シードでは ±1pt 程度のノイズが
乗るため、判断には 80シードを使った）:

| 指標 | 変更前 | 採用案 |
| --- | --- | --- |
| 18人3コート 上位3×下位3 | 5.0% | 4.8% |
| 18人3コート 序列差 | 8.01 | 8.00 |
| 21人3コート 上位3×下位3 | 2.3% | 2.7% |
| 21人3コート 序列差 | 8.58 | 8.63 |
| 味方になった人数の種類（18人） | 7.7人 | 8.6人 |
| 試合数の最大差（18人） | 2.3 | 1.8 |

実力分離は誤差範囲、試合数の公平性はむしろ改善。

## テスト

`src/lib/algorithm.test.ts`

- `formTeams`: `matchHistory` 省略時は従来どおり / 序列に余裕があれば履歴の少ないペア分けを
  選ぶ / 余裕がなければバランス優先でデフォルトのまま
- `assignCourts`: 優先度が同点なら過去の重複が少ない4人が選ばれる

## 非対象

- 実力帯をまたぐ多様性。分離の意図と正面から衝突するため上げない
- 3コート以上の逐次配置（1コートずつ貪欲）の全体最適化
