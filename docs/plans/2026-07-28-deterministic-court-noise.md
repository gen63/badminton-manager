# 2コート振り分けの乱数を決定的にする

2026-07-28

## 課題

`assign2CourtsHolistic`（2コート同時配置）のコート振り分けに `Math.random()` を
使っていた。

```ts
score: probC1 + Math.random() * COURT_ASSIGN_NOISE,
```

ランダム性自体は**意図的**（上位/下位グループの行き来を作り、コートが固定化しないよう
にするため）だが、`Math.random()` だと次の問題がある。

- 同じ状態から同じ結果を**再現できない**ため、バグ報告の再現ができない
- シミュレーションによる評価ができない。実際、2コート条件の計測値が実行ごとに
  ±1〜2pt ぶれ、他の改善の効果測定を妨げていた
- ユニットテストが書けない

## 変更

分布・強度はそのままに、**セッション状態から導出したシード付き乱数**に置き換える。

- シードキー: `${matchHistory.length}:${targetCourtIds}:${選出メンバーのID列}`
  - 試合履歴の長さ → ラウンドが進めば変わる
  - 対象コート ID → 同一ラウンドに複数の2コート組があっても区別できる
  - 選出メンバーの ID 列 → 同じラウンドでも人が入れ替われば変わる
- ハッシュは FNV-1a（32bit）、乱数は mulberry32。どちらも小さな純関数で、外部
  ライブラリは追加していない。`Math.random()` と同じ `[0,1)` の一様分布

`Math.random()` は ID 生成（トースト・通知・セッション ID）にも使われているが、
配置アルゴリズムとは無関係なのでそのまま。

## 検証

- **決定性**: `bench.ts` を2回実行して**完全一致**（変更前は2コートの行が毎回ぶれていた）
- **分布が変わっていないこと**: 2コート条件の指標は変更前後で誤差範囲
  （10人2コート 上位3×下位3 63.6% → 63.6%、8人2コート 85.2% → 84.6% など。
  変更前は同じ条件を2回実行するだけで 11.3% → 12.4% 程度ぶれていた）
- **3コート以上は完全一致**（この経路は元々乱数を使っていない）
- 配置時間の悪化なし

## テスト

- 既存の「ランダム性のある配置が行われる」は「同じ入力を複数回呼ぶと結果が異なる」
  ことを検証していたが、決定化と正面から矛盾する。**試合履歴を伸ばしてシードを
  変えると結果が変わる**ことを確認する内容に書き換えた（元の意図＝上位/下位の
  行き来が起きること、は保たれている）
- 新規: 同じ入力で `assignCourts` を10回呼んで**全て同じ結果**になることを確認
