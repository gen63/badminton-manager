# ダブルス自動配置ルールの単純化（共通通貨「偏差何点分」）

日付: 2026-10-02 / ブランチ: `claude/simplify-scoring`（基点 7fc3d63 = master）/ push・本番反映なし

## 背景

目的関数は改修を重ねて項目・係数が増え（`DEFAULT_WEIGHTS` / `VARIETY_SHAPE` / `STRENGTH_SHAPE` /
`RANK_GAP_SOFT_SHAPE` / `RECENCY_STREAK_SHAPE` ほか）、単位がバラバラで重みの意味が読めない。
すべてのソフト項を **「偏差（登録レートをその日のロースターで偏差値化: 平均50・SD10）何点分の悪さか」** に揃え、
1枚の点数表（`SCORE_TABLE`、`pairing/objective.ts`）に集約した。コストは単なる足し算（重みの掛け合わせも 0〜1 の正規化もない）。

## 点数表（調整後。コスト = 1コート/1ラウンド当たりの合計点。小さいほど良い）

| 悪さ | 点 | 初期案 → 調整 |
|---|---|---|
| コート内の最大−最小（偏差）`courtSpan` | 1点につき **2.5点**。偏差20（`courtSpanKnee`）を超えた分はさらに **+5点**/点（`courtSpanExcess`） | 1点につき1点 → 凸形が必要（下記） |
| チーム平均の差（偏差）`teamDiff` | 1点につき **3点**（= 偏差合計の差 × 1.5） | 2 → 3 |
| 3人以上一致（過去の3人組。鮮度で減衰）`tripleRepeat` | **28点** × 鮮度（0〜1）を、コートの4つの3人組ぶん足す（4人一致は最大112点） | 8 → 28 |
| 2連続目 / 3連続目 / 4連続目以上 `streak` | **5 / 25 / 100点** | 2 / 10 / 40 |
| 男女3対1 / 男男vs女女 / 4-0（少数派が少ないときのみ）`genderOn` | ON: **40 / 30 / 20点** | 6 / – / – |
| 同上（男女比調整 OFF）`genderOff` | OFF: **12 / 14 / 6点** | 1 / – / – |
| 希望ペア（normal）が味方にならない `pairPref` | **50点**（1組あたり。別コート・ベンチ・同コートで敵のすべて） | 5 → 50 |
| 試合数の公平性 `fairnessPerGame` | 出場者×控えの組で「出場者のほうが試合数が多い」逆転ごとに **15点**。**2試合分の逆転は4倍、3試合分は9倍**（二乗。`fairnessCapGames`=3で頭打ち） | 1試合分の逆転につき15点（線形）→ 二乗 |
| 後半均等化モードの公平性 `lateFairnessMultiplier` | 公平性を **4倍** | 新設 |
| （ハード）コート内の偏差の最大−最小 `extremeSpan` | **30以上は違反** | 初期案: 試算で決める |

偏差は 3σ（偏差 20〜80）で丸め、レート未設定は偏差50。

### 初期案から変えた理由（計測で必要だったもの）

- **男女・ペア希望は桁が違った**: 旧エンジンの「男女3対1 weight 3.7」「affinity 3.6」は、チームの釣り合い（weight 1.0）の約 100〜130 倍（偏差合計1点 = 1/35 の単位）。
  初期案の 6 点・5 点では 3-1 も同居敵も旧エンジンに大きく負けた。bench で 3-1%・男女戦%・希望ペア成立率を master 同等以上にする値を探した
  （ON 40/30/20、OFF 12/14/6、pairPref 50。OFF は master より 3-1 / 男女戦とも少ない）。
- **コート内の最大−最小は凸形が必要**: 線形（1点につき1〜2点）では実メンバー試算の「差25以上」「差30以上」が master の約 2 倍だった
  （master の skillGap は knee 超えで二乗の凸形）。knee 20 超えの上乗せを足して初めて master 以下になった。
- **公平性は線形ではなく二乗の逆転**: 線形（合計差）では端の人（偏差の極端な人）が 1〜2 試合遅れて試合数偏り（最多−最少）が master より悪化。
  逆転を二乗にして初めて master 同等以上になった。**全列挙で試合数偏りが悪化した過去の経緯は、この明示的な公平性の点で解消できた**（実メンバー試算）。
- **3人以上一致は「最新の共演の鮮度」だけ**: 同じ3人組が何度出ても足し込むと、小人数（8〜12人）で「待っている同じ4人」の点数が青天井になり公平性を押しのけた。
- **公平性の単位**: 優先度スコアを「1試合分」（滞在時間ベースは `computeOneGameDelta`、試合数ベースは `GAMES_PLAYED_SCORE_UNIT`）で割って試合数換算にした。

## 項目（7項目）とハード（3つ）

項目: 試合数の公平性 / コート内の最大−最小 / チーム平均の差 / 3人以上一致 / 連続 / 男女バランス（3-1・男男vs女女・4-0）/ ペア希望（normal）。
ハード（点数ではなく違反数で、必ず点数より先に最小化）: ①公平性の窓（`lateBalanceMode` の比率 0.7 / 0.3 も維持）
②ペア希望「必ず」（strong。(a) 同コートなら味方 (b) 2人一緒に出るか2人とも控える。2人の間の差は②の判定から除外）
③極端な実力差（偏差差が30以上。人数に関係なく適用）。

撤去したもの: fairness+waiting（→公平性1項）、skillGap の順位/数値混合と `RANK_GAP_SOFT_SHAPE`、competitive の順位版、
variety のペア項・同4人項・`VARIETY_SHAPE` の指数形、`RECENCY_STREAK_SHAPE` と連続のハード側、mixSplit、順位差ハード（14人以上・2/3）、
`reachableCount`、ハシゴ式による強さ補正（`ladder`=0 だったので強さの数値は不変だが、順位ベースのハード・初期解・タイブレーク経由の効きは消えた）、
`DEFAULT_WEIGHTS` / `GENDER_BALANCE_OFF_WEIGHTS` / `AFFINITY_ENEMY_COST*` / `strength.ts`。旧エンジン（`useObjectiveEngine: false`）・シングルスは未変更。

## 選び方

- 1コート（連続モード・次の試合の予測）: 窓内の候補から4人の全組み合わせ × チーム分け3通りを全列挙し、（違反数, 点数）が最小のものを採る
  （同点は優先度順で先に出てくる組。全滅時も違反最小→点数最小で必ず返す）。コート単位の採点はキャッシュ。
- 複数コート一括: 優先度上位から作った初期解（「必ず」ペアは2人セットで同じコートへ）を、従来と同じ決定的な局所探索（最急降下）で改善。

## 追記: 余り人数に応じた公平性（少人数の試合数偏りの改善）

### 原因

少人数（8人1C / 12人2C）で試合数偏りが悪化したのは、(1) 窓の内側で「3人以上一致（最大112点）」が「試合数の逆転（15点）」に勝つ、
(2) **ハードの「極端な実力差」が公平性より先に効く**（違反数は点数より先に比べる）、の2つ。(2) は公平性の点数を上げても効かない（8人1C は公平性1000点でも変わらなかった）。

### 変更（すべて余り人数 = 候補 − 必要人数 の連続関数。人数で段差はない）

1. **公平性の倍率** `fairnessSurplusFactor(余り) = 1 + 30 × exp(−(余り ÷ 3)²)`（ガウス型。`fairnessSurplusGain`=30, `fairnessSurplusScale`=3）。
   指数（exp(−余り÷scale)）だと余り 6〜7（実メンバー 18〜19人）でも 1.5〜1.9 倍になり、差25以上が 5.2→8.1 に悪化したので、余り 7 でほぼ 1 倍になる形にした。
2. **極端な実力差をハードから重い点数へ**: `extremePenalty` 400 + 超えた偏差1点につき `extremePerPoint` 40。
   さらに余り人数の倍率 `extremeSurplusFactor` を掛ける（余り ≤4 で 0、≥6 で 1、間は直線 = 段差なし。`extremeRampStart`=4, `extremeRampEnd`=6）。
   余り 6 以上（実メンバー規模）は他の項より桁違いに重く、実質ハードのまま。ハードは「公平性の窓」「ペア希望の必ず」の2つになった。
3. **後半均等化**: 公平性の倍率 4 → **2**、窓の比率 0.3 → **0.5**。倍率 4 はレベル差の悪化が大きかった（下記）。

## 追記: 当日の試合結果による偏差の補正（レート未設定者）

ハシゴ式を外したため、レート未設定の人（偏差50固定）は1日中補正されなかった。**履歴の勝敗から当日の強さを推定して偏差を補正する**（`pairing/deviation.ts` の `buildBlendedDeviationById`）。

- 当日推定: 履歴画面の「強さ偏差値」と同じ正則化付き Bradley-Terry の θ（`performanceRating.ts` の `estimateStrengthsById`。勝敗の無い試合・空チームは数えない）。
  **勝敗確定試合がある人の θ の平均・SD で 平均50・SD10 に標準化**し、±3σ（偏差20〜80）で丸める。登録レート由来の偏差（ロースター平均50・SD10）と同じ物差しにするため。
- 補正（全員に同じ式）: 偏差 = 事前 + w × (当日推定 − 事前)。事前 = 登録レート由来の偏差（未設定は 50）、w = n ÷ (n + k)、n = 勝敗確定試合数。
  試合数0の人は補正なし（50 / 登録のまま）。k は未設定 `kUnrated`・レートあり `kRated` で別（`DAY_ESTIMATE`。bench / テストが上書きできる）。
- 決定的: 履歴の値だけから決まる（`Date.now()` 非依存）。補正する人が居ない設定（全員レートありで `kRated=∞`）では BT を解かず、従来と完全に同じ結果。
- 採用値: **`kUnrated`=4**（1試合目 w=0.2、3試合目 0.43、10試合目 0.71）、**`kRated`=∞（レートありは補正しない）**。

## 追記3: レートありの人の「外れ値補正」（成績が偶然の範囲を大きく超えたときだけ）

背景: 「レートはあるが当日極端に不調／好調な人」が配置で考慮されない。kRated を有限にすると
（実力一定・登録正確の前提では）悪化したため、普段どおりの人は触らず、**外れ値だけ**補正する。

- 判定: 登録偏差から勝率を見込み（チーム平均偏差の差 × 0.115 の対数オッズ。bench の真モデルと同じ較正）、
  期待勝数との差 ÷ 二項分布の標準偏差 = z（履歴画面の「期待比 ±σ」と同じ考え方。ただし期待は当日推定でなく
  登録偏差由来）。勝敗確定 5 試合未満は対象外。
- 補正: e = |z| − outlierZ（超過分）。重み w = e ÷ (e + 1)。偏差 = 登録偏差 + w × (当日推定 − 登録偏差)、
  登録偏差から ±15 まで。当日推定が成績と逆向きなら補正しない。未設定者（kUnrated=4）は不変。決定的。
- 計測（実メンバー練習1:19人/練習2:18人、3コート、200シード）。しきい値 2σ だと**普段どおりでも
  毎回のように誤発動**（1練習あたり約2人・9割の練習）し、試合数偏り・差30以上がわずかに悪化。
  理由: 判定を試合ごとに繰り返す（何度も覗く）ため、偶然で 2σ を越える機会が増える。
  2.5σ なら誤発動は約0.5人/練習で普段どおりは補正なしと同等、3σ はほぼ誤発動なし（ただし効果も出ない）。
- 効果は小さい（1日10〜12試合では検出力が低い）。極端にずれた人（±25）の絡む試合のチーム平均差が
  1〜1割弱減る程度。採用は 2.5σ・K=1・上限15。
