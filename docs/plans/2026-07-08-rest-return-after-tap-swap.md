# タップ交換で出場した休憩者の試合後復帰先の修正

- 日付: 2026-07-08
- ブランチ: `claude/rest-area-return-logic-ectwgu`

## 背景 / 課題

2026-05-25 のコミット 4a73cdc（予約と休憩の連動）で、タップ交換で出場した
休憩者を試合後に休憩へ戻す `court.restingPlayerIds` 機構が削除され、
試合後の復帰は「未成立予約があれば休憩、なければ待機」の統一ルールに
一本化された。その結果、次の 2 つの不満が生じている:

1. **手動で休憩中のメンバー**をタップ交換で出場させると、試合後に
   **待機**へ行ってしまう。→ 休憩エリアに戻ってほしい。
2. **予約で休憩中のメンバー**をタップ交換で出場させても予約が
   `pending` のまま残るため、試合後にまた**休憩**へ戻ってしまう。
   → 予約は消化されたものとして待機エリアに戻ってほしい。

## 確定仕様

試合終了時の復帰先ルール:

1. **休憩からタップ交換で出場したメンバーは試合後に休憩へ戻る**。
   ただし、そのメンバーが未成立予約に含まれる場合（= 予約による休憩）は
   タップ交換でも「休憩へ戻す」対象にしない（下記 2 のルールに委ねる）。
2. **未成立予約のメンバー全員がその試合に出場していた場合、予約を
   `fulfilled` として消化する**。これにより手動タップ配置でも
   自動配置（GAMEOPS1 / autoAssignAndFulfill）と同様に予約が消化され、
   メンバーは試合後に待機へ戻る。
3. 上記以外は従来どおり: 未成立予約を持つメンバーは休憩
   （次の予約待ち。2026-05-25 の合意仕様を維持）、それ以外は待機。

補助ルール:

- タップ交換で出場した「休憩へ戻る予定」のメンバーが試合途中で
  コートから外された（別メンバーと交換された）場合は、その場で休憩へ戻す。
- コート間スワップ（swapPositions）ではフラグを移動先コートへ引き継ぐ。

## 変更内容

- `src/types/court.ts`
  - `Court.restingPlayerIds?: string[]` を復活（試合後に休憩へ戻すメンバー）。
  - `EMPTY_COURT_STATE` に `restingPlayerIds: []` を追加
    （コートクリア時に必ずフラグが消えるように）。
- `src/services/sessionMutations.ts`
  - `swapPlayer`: 休憩中メンバーを入れたとき、未成立予約に含まれなければ
    `court.restingPlayerIds` に積む。外れたメンバーがフラグ保持者なら
    その場で `isResting=true` に戻し、フラグを除去。
  - `swapPositions`: 異コート間スワップでフラグを移動先コートへ移す。
  - `computeRemovePlayer`: `restingPlayerIds` からも除外（DATA1 と同様）。
- `src/lib/gameOperations.ts` `computeFinishAndContinue`
  - finish step2 の前に、未成立予約でメンバー全員が本試合の出場者に
    含まれるものを `fulfilled` にする。
  - 復帰判定を `isResting = restingPlayerIds に含む || 未成立予約を持つ`
    に変更（未成立予約の判定は消化後の予約リストで行う）。
  - 連続モード配置・GAMEOPS1 の予約参照も消化後のリストを使う。
- テスト: `gameOperations.test.ts` / `sessionMutations.test.ts` に
  上記ルールのケースを追加。

## 影響しない挙動

- 予約作成時にメンバーを休憩化する挙動（computeAddReservation）は不変。
- 自動配置（予約成立で休憩から呼び出し → 試合後待機）は不変。
- 試合中に予約を作ったメンバーが試合後に休憩へ回る挙動（次の予約待ち）は不変。
- コート手動クリア（試合不成立）は従来どおり全員待機へ
  （フラグは EMPTY_COURT_STATE で消える）。
