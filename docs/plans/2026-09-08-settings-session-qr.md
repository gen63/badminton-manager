# 設定画面にセッション参加 QR を表示する

- 日付: 2026-09-08
- 対象: `src/pages/SettingsPage.tsx` / `src/components/SessionQrCode.tsx`（新規）

## 背景

`2026-08-18-settings-session-url-copy.md` で、2026-05-07 に撤去したセッション URL 共有の
うち **設定画面の URL コピーだけ** を緊急避難措置として復活させた。そのときは
「QR・作成完了後の URL 画面・参加画面の共有アコーディオンは戻さない」と決めていたが、
実運用で以下が分かったため QR も復活させる。

- URL コピーは **送る手段（LINE 等）がある相手** にしか使えない。体育館でその場に
  いる人へ渡すには、相手に URL を送るより **画面を見せて読ませる** 方が速い。
- セッション ID は 6 文字とはいえ、URL を口頭・手入力で伝えるのは打ち間違いが多い。

## 決定

設定画面の既存「セッションURL」カードに QR を **常時インライン表示** する。

- 開閉トグルにはしない。緊急時に「設定を開いて見せる」だけで完結させるため、
  タップ段数を増やさない。
- 表示位置は URL テキストの**上**。カードの主役が QR、URL テキストとコピーボタンは
  従来どおりのフォールバックという序列にする。
- 権限分岐は入れない（既存の URL カードと同じく全員に見える）。信頼モデルは
  CLAUDE.md のとおり「URL を知っていれば誰でも参加できる」ままで、QR は URL の
  別表現にすぎず新しい権限境界を作らない。

## 実装方針

- **エンコードはライブラリに任せる**: `qrcode.react`（v4, ランタイム依存ゼロ・
  React 19 対応）の `QRCodeSVG` を使う。QR は Reed-Solomon とマスク選択を含む
  仕様で、自前実装は誤り検出が難しく保守コストに見合わない。
- **`src/components/SessionQrCode.tsx` に切り出す**: `SettingsPage.tsx` は既に 880 行
  あるため、QR のサイズ・余白・色などの表示仕様はコンポーネント側に閉じ込め、
  ページからは URL を渡すだけにする。テストもコンポーネント単位で書ける。
- **URL の組み立ては既存の `buildSessionUrl` を再利用**（コピーボタンと同じ値を
  そのまま渡す）。QR とコピーで別々に組み立てると片方だけ壊れる余地が生まれる。

### 表示仕様（スキャンできることを優先）

- サイズ 192px（8pt グリッドの 24 の倍数）。スマホ画面で 30cm 程度離れても読める。
- 誤り訂正レベルは `M`。セッション URL は 50 文字程度の ASCII なのでバージョンは
  小さく収まり、`M` でも余裕がある（`H` にするとモジュールが細かくなり逆に読みにくい）。
- **背景は常に白・前景は黒**をハードコードし、テーマ変数（`--color-muted` 等）は
  使わない。QR はコントラストが命で、地色が変わると読めなくなるため。
- 白背景の外周に padding を持たせ、`marginSize` で仕様上のクワイエットゾーン
  （静粛領域）も確保する。カード背景と QR が接するとスキャナが枠を認識できない。
- 装飾（ロゴ埋め込み・角丸のモジュール等）は入れない。

## テスト

`src/components/SessionQrCode.test.tsx`

- URL を渡すと SVG が描画される
- `aria-label` / `role="img"` でスクリーンリーダーに用途が伝わる
- 与えた URL が SVG の `value` として反映されている（`data-testid` 経由で確認）

## やらないこと

- 作成完了後の URL 画面・参加画面の共有アコーディオンの復活（2026-05-07 の撤去理由
  である「導線が多すぎる」は変わっていない）
- QR のタップ拡大・全画面表示（192px で足りるか実運用で見てから判断する）
- QR の画像保存・共有シート連携
