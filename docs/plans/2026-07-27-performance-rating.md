# その日の強さ指標（パフォーマンスレート / 強さ偏差値）

2026-07-27

## 背景 / 要望

履歴画面には管理者（作成者・開発モード）向けに勝率を出しているが、
**勝率だけでは「弱い相手とばかり当たった結果の高勝率」と「強い相手に勝った
高勝率」を区別できない**。その日のセッション内で、対戦相手・味方の強さを
加味した「どの程度のパフォーマンスだったか」を出したい。

## 決定事項（ユーザー確認済み）

| 項目 | 決定 |
| --- | --- |
| 指標の形式 | レート（1500基準）＋強さ偏差値（平均50）＋補助指標 |
| 表示場所 | 履歴画面の成績サマリ ＋ セッション内ランキング一覧 |
| スコア反映 | 勝敗のみ（得点差は使わない） |
| 表示権限 | **開発モードのみ**（`useDevMode()`。勝率の `isCreator()` とは別条件） |

## 算出方式: 正則化付き Bradley-Terry

その日の全試合を連立で解き、各メンバーの強さ `θ`（自然対数オッズ単位）を
同時推定する。「誰と組んで誰と当たったか」が全体の整合性として効くため、
弱い相手にしか勝っていない人の θ は上がらない。

### モデル

- チーム強さ = メンバーの θ の**平均**（シングルス＝1人平均なのでダブルスと
  同じスケールに乗る）
- `P(A が勝つ) = sigmoid(mean(θ_A) - mean(θ_B))`
- 目的関数 = 対数尤度 − `λ/2 · Σθ²`（L2 正則化）
  - 正則化がないと全勝者の θ が発散する（完全分離）。試合数が少ない人ほど
    平均（θ=0）へ引き戻される、という期待どおりの挙動になる。
  - `λ = 0.5`（`PRIOR_STRENGTH`）。事前分布の重みが約 2 試合分に相当し、10戦
    全勝で概ね +360 レート程度に収まる。λ=1.0 も試したが、少数試合の圧縮が
    強すぎて「弱い相手に全勝」と「互角の相手に勝ち越し」がほぼ同点になった
    （16人48試合のシミュレーションと単体テストで確認して 0.5 を採用）。

### 解法

対角ニュートン法（座標ごとに `θ += g / h`）を最大 500 反復。

- `g = Σ(実績 − 予測)/n − λθ`、`h = Σ p(1-p)/n² + λ`
- 1 反復あたりの更新量は ±0.5 にクランプ（対角近似の踏み込み過ぎ防止）
- 全 θ に定数を足しても尤度は不変だが、L2 が θ の中心を 0 に固定するため
  最適解は一意。順序依存もない（オンライン Elo と違い再現性がある）。

### 表示値への変換

- **レート** = `1500 + θ · 400/ln10`（400点差 = 勝率10:1。Elo 慣習に合わせる）
- **強さ偏差値** = `50 + 10 · (θ − mean) / sd`（母集団は勝敗確定試合が1つ以上
  ある人。`sd ≈ 0` のときは全員 50）
- **対戦相手平均レート / 味方平均レート** — 「誰と当たったか」の説明用
- **期待勝率・期待勝利数** — その人の枠に**平均的な選手（θ=0）**が入った場合の
  勝利期待値。`実勝利数 − 期待勝利数` が「相手の強さを補正した上振れ分」に
  なり、要望の核心（弱い者同士で勝っても評価されない）に直接答える。

## 実装

### `src/lib/performanceRating.ts`（新規・純関数）

```ts
computePerformanceRatings(matches: Match[], players: Player[]): PerformanceResult
findPerformance(result: PerformanceResult, name: string | null): PlayerPerformance | null
```

- `PlayerPerformance`: `name / wins / losses / total / winRate / rating /
  deviation / opponentRating / partnerRating / expectedWins / expectedWinRate /
  winsAboveExpected`
- 集計キーは**名前**（既存 `matchFilter.ts` と同じ方針。同名は区別しない）
- `winner` が無い試合は除外。`players` に無い ID は枠ごと除外し、片チームが
  空になる試合はスキップ
- 並びはレート降順（同点は勝ち数 → 五十音）

### `src/pages/HistoryPage.tsx`

- `showPerformance = devMode`
- 成績サマリ（`PlayerRecordSummary`）に 2 行目を追加: レート / 偏差値 /
  対戦相手平均 / 期待勝率との差
- `PerformanceRanking`: 折りたたみ式（既定は閉じる）のランキング表。順位・名前・
  レート・偏差値・勝敗・対戦相手平均・期待比を列挙。行タップでそのメンバーの
  フィルタに切り替える
- 勝率の表示条件（`isCreator()`）や既存フィルタの挙動は変更しない

## テスト

`src/lib/performanceRating.test.ts`

- 空入力 / 未入力試合のみ → 空結果
- 完全対称なデータ → 全員レート 1500・偏差値 50
- **弱い相手に全勝した人より、強い相手に勝ち越した人のレートが高い**（要望の核）
- シングルス、解決できない ID の混在
- 収束チェック（最適解での勾配が概ね 0）
- 偏差値の平均が 50 / 標準偏差が 10

## 非対象 / 制限

- 集計はそのセッションの `matchHistory` に閉じる（日をまたぐ通算は対象外）
- 得点差は使わない（勝者のみ記録モードでも同じ基準で計算できることを優先）
- `Player.rating`（管理者が事前に入れる想定値）は入力にも出力にも使わない。
  混同を避けるため UI 上は「レート（本日）」と明示する
- 試合数が少ない人は正則化で 1500 付近に寄る。UI では試合数を併記して判断材料
  にする
