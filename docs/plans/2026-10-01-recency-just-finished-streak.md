# 連続出場を嫌う制御の作り直し（「たった今終わったコートの人」を段階的に避ける）

2026-10-01（元 plan: `2026-09-08-recency-penalty.md`）

## 背景

運用はほぼ「連続モード」（試合終了ボタン → `computeFinishAndContinue` が同じコートへ即配置）。
最近多い **19人3コート**（待機 11 人 = 今終わった4人 + その他7人）を連続モードで測ると、
既存の目的8 `recency` はほとんど効いていなかった（重み 1.2 と 0 で結果がほぼ同じ）。

変更前の計測（`/tmp` の sim: 19人3コート・30シード×60試合）:

- 直前試合の4人の再選出 平均 **0.99 人/試合**（**全部回避可能だった**）
- 選出者の連続回数: 1連続 75% / 2連続 21% / 3連続 3.5% / 4連続 0.4% / 5連続 0.1%

原因は4つ。

1. **連続の定義が悪い**: `RECENCY_SPAN` ＝コート数で「出場間隔 < コート数」を連続とみなしていた。
   複数コートでは待機者のほぼ全員が streak>=1 になり、「たった今終わった人」と
   「少し前に終わった人」を区別できない
2. **形が飽和**: streak=2 で満点。3連続・4連続を強く避けない
3. **重みが弱い**: 1.2。配置人数の平均で割る形でもあり、1人あたりの効きが薄い
4. **`hasSimilarRecentMatch`（直近3試合と3人以上重複を禁じるハード制約）**:
   余剰の小さい条件では、完全ローテーション（残りの4人をそのまま入れる）が
   「直前の前の試合と4人重複」で禁じられ、直前メンバーの混入が強制される

## 仕様（ユーザー決定）

1. **連続の判定**: 「たった今終了したコートに居た人」だけが連続候補（時刻ベース）
2. **段階的ペナルティ**: 今回入れると何連続目になるかで増やす。2連続目は軽く、
   3連続目はかなり減らし、4連続目以上は人数的に不可避なとき以外ほぼ起きない。**飽和させない**
3. 小さい候補プールで `hasSimilarRecentMatch` が連続回避を妨げる問題の緩和
4. **強さバランス（実力差・順位幅・男女構成）を悪化させない。** 2連続の回避は強さバランスより
   優先しない。3連続以上の回避と強さがトレードオフになるなら数値で示す（下の「トレードオフ」）

## 設計

### 1. 連続（streak）の定義 — `src/lib/pairing/streak.ts`

`buildStreakById(matchHistory, inProgressStartedAt)`。Match の `startedAt` / `finishedAt` と、
**進行中コートの開始時刻**だけで決まる。`Date.now()` に依存しない（決定的）。

- streak > 0 ⇔ その人の**最後の試合の `finishedAt` 以降に、他の試合が1つも開始していない**
  （履歴上の試合と、現在進行中コートの試合の両方を「他の試合」に数える）。
  連続モードでは「今終わったコートの4人」がちょうどこれに当たる。手動配置でも同じ定義で効く
- 過去へ遡り、その人の連続する2出場 k → k+1 の間（`finish_k` 〜 `start_{k+1}`）に他の試合の
  開始が無ければ連続としてカウント。streak ＝ 連続して出た試合数（直前1試合だけなら 1）
- **同時刻の扱い**: 開始の判定は `finish_k <= start < start_{k+1}`（下限を含む）。連続モードは
  終了と次の配置が同じ瞬間（同一 ms になりうる）に行われるため、同時刻の開始を
  「終了後に始まった試合」として数えないと、直前に終わった人が連続のまま残る。
  上限側は自分自身の次の試合を数えないので `start_{k+1}` を含まない
  （連続モードで即再配置された自分は、間が空なので連続）
- **旧データ**（`startedAt` / `finishedAt` が 0・非数）はその試合を判定不能とし、そこで連鎖を打ち切る
  （最新の試合が判定不能なら 0）。**減点しない側**に倒れる
- **自動終了の丸め**（`2026-09-30-auto-end-always.md`: `finishedAt = 開始 + 15分`）: 実際の終了より
  前の時刻になるので、丸めと実終了の間に始まった他コートの試合があれば連続は切れる。こちらも
  減点しない側に倒れるだけで破綻しない
- **進行中コートの開始時刻の渡し方**: `assignCourts` の新オプション `inProgressStartedAt?: number[]`。
  `courtStartTimes(courts)`（配置済みコートの `startedAt`、準備中で未設定なら `assignedAt`、どちらも
  無ければ無視）で作る。3つの呼び出し元（`MainPage.handleAutoAssign` /
  `computeFinishAndContinue` / `nextMatchPrediction.runScenario`）が同じ値を渡す。
  `computeFinishAndContinue` は対象コートをクリアした後の `updatedCourts` を渡す。
  省略時は履歴上の試合の開始だけで判定する

### 2. ペナルティの形 — `objective.ts`

```
n = streakOf(id) + 1                  今回出ると何連続目か（連続候補でなければ 1）
cost(n) = 0                           n = 1
cost(n) = base × growth^(n−2)         n >= 2        （既定 base=1, growth=4 → 1 / 4 / 16 / 64）
term    = Σ cost(n) / 4               （4 = 1コートの人数。配置人数の平均ではない）
```

- **飽和しない**。連続回数が増えるほど急に増える
- 配置人数の平均ではなく **1コートの人数 4 で正規化**: 複数コート一括配置でも1人あたりの効きが
  変わらない（旧: 12人配置だと 1/3 に薄まり、連続モードと効きが食い違った）。そのためこの項は
  0〜1 に収まらない（`ObjectiveTerms.recency` のコメントに明記）
- **ハード側**: `RECENCY_STREAK_SHAPE.hardFrom = 3`。3連続目以上になる配置は `assignRound` の
  `evaluate` で**違反**として数える（順位差・公平性の窓・直近重複と同じ辞書式）。ソフトのコスト
  だけでは他のハード制約に押されて 3連続が 0.7% 残った（19人3コート）が、違反にして 0 になった。
  4連続目以上の「実質ハード」はこれに含まれる。**避けられないとき（控えが居ない等）は配置を
  諦めない**（辞書式で最小の違反を選ぶだけ）

### 3. 重みの決め方

2連続目のコストは 1人あたり `base × RECENCY_WEIGHT / 4`。3連続目以上は違反なので、重みは
実質「**2連続目をどこまで避けるか**」を決める。19人3コート連続モード
（`CONTINUOUS=1 NOISE=4 SEEDS=200 ROUNDS=20`、hardFrom=3 / growth=4 / 緩和あり）:

| 重み | 2連続% | 3連続% | 3-1% | 幅広% | 実力幅 | 試合数幅 | 待ち |
|---|---|---|---|---|---|---|---|
| 0 | 22.3 | 0.2 | 5.1 | 11.5 | 8.54 | 1.37 | 8.65 |
| 1.2（旧値） | 17.5 | 0.0 | 5.5 | 11.1 | 8.48 | 1.35 | 8.31 |
| **2（採用）** | **15.7** | 0.0 | 5.8 | 11.2 | 8.51 | 1.37 | 8.20 |
| 3 | 13.5 | 0.0 | 6.5 | 11.6 | 8.56 | 1.36 | 8.03 |

重みを上げるほど 2連続は減るが、**男女構成（3-1%）が先に崩れる**（3 で +1.4pt）。
「2連続の回避は強さバランスより優先しない」ため、3-1% の悪化が +0.7pt 以内に収まる 2 を採った。
重み 100 まで上げても 2連続は 12% 残る（公平性の窓・順位差・直近重複などのハード制約で
避けられない分。ablation: `hasSimilarRecentMatch` なしで 8%、さらに窓なしで 6%、順位差なしで 4%）。

**growth** は、`hardFrom=3` では 3連続目以上のコストは違反どうしの優先付けにしか使われないので、
結果にほぼ効かない。4 を採った（ハードにしない場合の目安として、3連続目のコストを
2連続目の 4 倍に留める）。
**hardFrom** は 3 と 4 を比較し、3 は 3連続% を 0.3〜0.9 → 0.0 に下げるのに 3-1% は動かない
（18人3コート 7.8 vs 8.0 / 19人3コート 6.0 vs 6.0 / 16人2コート 4.3 vs 4.2）ので 3 を採った。

### 4. `hasSimilarRecentMatch` の緩和

直近重複のハード制約が**連続回避と、強さ・男女構成の両方を妨げる**ことを ablation で確認した
（19人3コート連続モード、hardFrom=3 / w=1.2、SEEDS=100）:

| 直近重複 | 幅広% | 実力幅 | 3-1% | 試合数幅 | 待ち | 2連続% | 占有率% | 共演 |
|---|---|---|---|---|---|---|---|---|
| 3人重複を禁じる（従来） | 13.4 | 8.84 | 7.5 | 1.91 | 8.76 | 19.9 | 38.0 | 14.98 |
| 4人全員一致のみ禁じる | 11.0 | 8.48 | 5.7 | 1.35 | 8.33 | 17.5 | 41.5 | 14.39 |

8人1コートでは 3-1% が 21.8% → 5〜6% に激減する（完全ローテーションが許される）。
**質 > 多様性 > 公平性**（`DEFAULT_WEIGHTS` の優先順位）に従い、強さ・男女構成・試合数・待ちが
揃って改善する側を採り、**占有率（目的6 多様性）の悪化を代償として受け入れる**。

ただし多様性の代償は大きい条件に限りたいので、**条件付き**にした（`algorithm.ts`）:

- 控えの余剰人数（候補 − 配置人数）が **8 以下（＝控えが2コート分以下）**、かつ
  **連続候補（streak>0）が居る**ときだけ、`hasSimilarRecentMatch` の重複上限を 3 → 4 にする
  （4人全員一致＝同じ顔ぶれの再演は引き続き禁止）
- 連続候補が居ない（履歴が空・時刻が無い旧データ）ときは緩める理由が無いので従来どおり
  （これで既存テスト「6人で直近試合と3人以上かぶらない」も不変）
- 余剰 9 以上（21人3コート連続モード等）は効果が小さく占有率の代償が相対的に大きいので従来どおり
- レガシーエンジンや他の呼び出し（`hasSimilarRecentMatch` の他の使用箇所）は変えない

閾値 8 は、19人3コート（余剰7）・16人2コート（余剰8）・20人3コート（余剰8）を含み、
21人3コート（余剰9）を含まない位置。**切り替わり目が段差になる**点は懸念（報告参照）。

## トレードオフ（強さバランスとの関係）

1. **占有率（多様性）の悪化が最大の代償**。19人3コートで 37.6 → 42.0（+4.4pt）。原因は全て
   直近重複の緩和（上の ablation 参照。緩和しなければ 38.0 のまま）。**緩和しない場合は
   19人3コートの 3-1% が 7.5（+2.1pt）、幅広% 13.4（+0.6pt）になる**。閾値は
   `SMALL_POOL_MAX_SURPLUS`（algorithm.ts）で切り替えられる
2. **3連続以上の回避と男女構成**: 19人3コートでは 3-1% が +0.4pt に収まる。ただし
   **15人3コート（余剰が3人しかない構成）では 3-1% が 16.9 → 25.6**。
   内訳: 回避しない（hardFrom=0, w=0）なら 3-1% 10.1 だが 3連続 14.4% / 4連続+ 14.6%
   （同じ人が出ずっぱり）。3連続目をハードにすると 3連続 7.4% / 4連続+ 2.0%、3-1% 23.0%。
   **性別の都合で出ずっぱりになる人を、3-1 を許して休ませている**。ユーザー決定
   「4連続以上は人数的に不可避なとき以外ほぼ起きない」に従ったが、**3-1 を嫌う運用なら
   `hardFrom` を 4 にしても 3-1% は 24.2 と大差ない**（コストの `growth` で効く）ため、
   この構成は連続回避のコスト（重み）を下げる以外に手が無い
3. 2連続は **12人2コート・15人3コートでは減らない**（26.7→26.5 / 26.3→38.1）。待機が
   「今終わった4人 + 3〜4人」しかなく、そもそも1人以上は連続になる（不可避）。3連続・4連続へ
   伸びるのを止めた結果、2連続に寄っている
4. 他の強さ指標（幅広%・競り度・実力幅）は全条件で横ばい〜改善（直近重複の緩和の寄与が大きい）
