# ヘッダー項目をボトムナビゲーションに移動

**日付**: 2026-03-06
**目的**: ヘッダーの渋滞解消。予約・履歴・設定を画面下部の常時表示ナビに移動。

---

## 現状の問題

MainPage のヘッダーにボタンが7つ密集している：

| 左側 | 右側 |
|------|------|
| 連続モード | Undo |
| 一括割当 | Redo |
| 予約 | 履歴 |
| | 設定 |

→ 小さい画面ではタップしにくく、視覚的にも渋滞。

---

## 変更内容

### 1. BottomNav コンポーネントを新規作成

`src/components/BottomNav.tsx`

- 画面下部に固定表示（`fixed bottom-0`）
- iOS セーフエリア対応（`env(safe-area-inset-bottom)`）
- 3項目を均等配置：

| アイコン | ラベル | 遷移先/動作 |
|----------|--------|-------------|
| CalendarCheck | 予約 | ReservationModal を開く |
| History | 履歴 | `/history` へ navigate |
| Settings | 設定 | `/settings` へ navigate |

- 予約のバッジ（pending件数）も移動
- 現在のページをハイライト表示
- タップターゲット: 44px以上（DESIGN.md準拠）

### 2. MainPage ヘッダーの整理

移動後のヘッダー（4ボタンのみ）：

```
[連続] [一括]          [Undo] [Redo]
```

- 予約・履歴・設定ボタンを削除
- ヘッダーがスッキリし、各ボタンに余裕が生まれる

### 3. MainPage のレイアウト調整

- `main` の `pb` を調整してボトムナビと重ならないようにする
- 既存の `pb-[280px]`（待機メンバー操作パネル用）にボトムナビの高さ分を加算

### 4. HistoryPage / SettingsPage への影響

- これらのページにはボトムナビを表示しない（戻るボタンで MainPage に戻る既存フロー維持）
- MainPage 専用のボトムナビとする

## デザイン仕様

```
┌─────────────────────────────┐
│  [連続] [一括]    [↩] [↪]  │ ← ヘッダー（スッキリ）
├─────────────────────────────┤
│                             │
│     メインコンテンツ          │
│                             │
├─────────────────────────────┤
│   📅予約    📋履歴    ⚙設定  │ ← ボトムナビ（常時表示）
└─────────────────────────────┘
```

### ボトムナビのスタイル

- 高さ: 60px + safe-area-inset-bottom
- 背景: `bg-background`
- 上部ボーダー: `border-t border-border`
- 影: `shadow-[0_-2px_10px_rgba(0,0,0,0.05)]`（上方向の微かな影）
- アイコンサイズ: 22px
- ラベル: `text-[10px]`
- アクティブ色: `text-primary`
- 非アクティブ色: `text-muted-foreground`
- z-index: `z-20`

## 実装の注意点

- 予約モーダルの開閉状態を BottomNav に渡す必要あり（props or callback）
- DESIGN.md の「重要なボタンは画面下部に配置」の指針に合致
- Fitts's Law: 親指が届く下部に頻繁に使う機能を配置
