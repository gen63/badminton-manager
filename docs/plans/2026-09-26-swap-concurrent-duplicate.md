# 同時操作によるメンバー二重表示の修正

## 問題
複数人が同時にメンバー交換をすると、同じメンバーが2箇所（2コート、または同一コートの2スロット）に表示されることがある。

## 原因
書き込みは transaction でアトミックだが、**操作の前提（画面で見ていたコートの並び）を transaction 内で検証していなかった**。
- `swapPlayer(courtId, position, newPlayerId)`: 入れるメンバーが、他端末の操作で既に別コートに入っていても、そのまま書いていた。
  例: 端末A・Bが同じ待機メンバー W を別々のコートに同時に入れる → W が2コートに乗る。
- `swapPositions`: 位置だけで入れ替えるため、他端末が先に交換していると意図しないメンバーを動かす。
- `autoAssignAndFulfill`: 配置はローカルの待機リストから計算するため、同時の交換/配置と重なると同じメンバーを二重配置しうる。
- 付随バグ: コートカードの描画が `teamA.filter(id => id).map((id, idx) => …)` で、空きスロットがあると idx が実ポジションとずれていた。

## 対応
transaction 内で前提を検証し、崩れていたら**書き込まずに `SessionError('conflict')`**（トースト「他のユーザーが更新しました」）。
- `swapPlayer`: 入れるメンバーが既にいずれかのコートにいる → conflict。`expectedOutgoingId`（画面上でそのスロットにいた人）と実際が違う → conflict。
- `swapPositions`: 各位置の `expectedPlayerId` と実際が違う → conflict。
- `autoAssignAndFulfill`: 配置メンバーが対象外コートに既にいる／配置内で重複 → conflict。
- 描画の idx は元配列のインデックスを使う。

自動で辻褄を合わせる（例: 既にいるなら位置交換に読み替える）案は、他端末の操作を黙って書き換えるため不採用。中止して画面を最新にし、やり直してもらう方が意図とずれない。
