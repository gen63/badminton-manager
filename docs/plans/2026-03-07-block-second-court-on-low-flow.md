# 流動優先時のコート配置ブロック強化

## 背景
ユーザーから「流動優先モードで待機が4人、2コートの場面では
2コート目の配置をブロックしてほしい」という要望があった。

現行ロジックでは `waitingCount < 3` でのみ手動/自動配置を止めており、
トータルメンバーがコート満杯（例：8人2コート）の場合、
空きコートが1つになると待機4人となってブロックされず、
先に空いたコートだけが順次埋まってしまう。
流動性を保つためには両コートが同時に空いたタイミングで
まとめて配置した方が望ましい。

## 変更内容
- `src/lib/utils.ts` に汎用関数 `shouldBlockForRotation` を追加。
  - 基本閾値(`baseThreshold`)に加え、
    `totalActive === totalCourts*4`（満員）かつ
    `emptyCourts < totalCourts` の場合もブロックする。
- `MainPage.tsx` のブロック判定・連続モード解除ロジックをこの
  関数に置き換え。
- 同関数を手動配置(`shouldBlockAssignment`)と連続モード用
  (`shouldBlockContinuous`)の両方で利用。
- テスト `utils.test.ts` に新関数の単体検証を追加。

## 効果
- 総員がコートキャパシティと同じときは、他コート終了待ちの
  ブロックが確実に働く。
- 2コート・8人の典型ケースでは、1コート目が終わっても
  2コート目は即時配置されず、両方終了時にまとめて割り当て
  される。流動性が高まる。
- 3コート以上でも同様の振る舞いが適用される。
