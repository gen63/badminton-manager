# 連続出場を少し嫌う（目的8 `recency`）

2026-09-08

## 背景

2026-09-08 の実データ（20人3コート・38試合）を分析したところ、**試合数の偏りは小さい
のに待ち時間の偏りが大きい**ことが分かった。

- 試合数: 6〜9（平均 7.6、幅 3）。前半19試合は全員3〜4回でほぼ完璧に均等
- 待ち: 「自分が出ていない間に行われた試合数」の最大が **11 試合**（3コートなので
  実時間で 25 分以上）の人が4人。一方で空き1〜2試合で回り続ける人もいる
  - みっちゃん: 空き `2,2,1,2,2,2` ＝ ほぼ連続（遅参加のキャッチアップ。正しい挙動）
  - すぎ / みさと: 空き `3,3,6,11,6` / `6,6,3,11,3` ＝ 一度も連続出場が無い

bench（`scripts/bench-court-assignment.ts`、本番エンジン `ENGINE=objective`、
21人3コート・13ラウンド・NOISE=4・30シード）でも現状は

```
試合数幅 1.37 / 待ち 9.53
```

で、**9〜10 試合待ちは設計どおり出る**（同日に直した自動終了バグとは別の構造的な話）。

原因は明確で、**配置の判断材料に「前回出場からの経過」が一切無い**こと。

- `calculatePriorityScore`（`algorithm.ts`）＝ 試合数（待機時間優先モードなら
  試合数 ÷ 滞在分）。経過時間は見ない
- 目的関数の目的2 `waiting` は名前に反して経過時間ではなく
  「優先度順位（＝試合数の順位）が最上位の人を控えに回していないか」
- `lastPlayedAt` を実際に使っているのは**シングルスのペアコストだけ**
  （`SINGLES_WEIGHT_RECENCY = 500`「直前プレイ者を含むペアは最優先で回避」）。
  ダブルスにだけ同等の仕組みが無いという非対称になっている

結果、試合数が並んだ人の中では、多様性・男女構成・序列差だけで選ばれる。
**回数は揃うが待ちは揃わない。**

## 方針

「長く待った人を優先」ではなく「**直前に出た人を少し嫌う**」として入れる。

| | 優先度スコアに待ち時間を入れる | 目的関数に `recency` 項を足す（採用） |
|---|---|---|
| 効き方 | 候補全体の並び順が変わる | 直前に出た人だけを弱く減点 |
| 試合数の均等 | 壊れうる（8試合の人が10分待てば6試合の人を追い越す） | 優先度順位を動かさないので保たれる |
| 遅参加のキャッチアップ | 弱まる | 重みを `fairness` 未満にすれば維持される |
| 前例 | なし | シングルスに実装済み |

## 設計

### 1. 指標（`objective.ts`）

**時刻ではなく試合履歴ベース**にする。`Date.now()` に依存すると bench が
非決定的になり、実運用でも端末の時計差に影響されるため。

```
gapOf(id)  = その人が最後に出場した試合から数えて経過した試合数
             （直前の試合に出ていた = 0、1試合はさんだ = 1、未出場 = ∞）
recency(id) = max(0, 1 − gapOf(id) / RECENCY_SPAN)
term        = 配置された全員の recency の平均（0〜1・小さいほど良い）
```

- `RECENCY_SPAN` は **コート数**（最低1）。3コートなら「1巡（3試合）休めば 0」。
  コート数で割ることで、面数が変わっても「1巡ぶん」の意味が保たれる
- 未出場（`gapOf = ∞`）は 0。初回保証（`gamesPlayed === 0` の `-Infinity`）と
  衝突しない
- 練習開始直後は履歴が空で全員 0 になり、この項は何もしない

### 2. 配線

- `ObjectiveWeights` / `ObjectiveTerms` に `recency` を追加し、
  `computeObjectiveTerms` / `weightedObjective` に1行ずつ足す
- `ObjectiveInput` に `recencyById: Map<string, number>`（値は `gapOf`）を追加
- `AssignRoundParams` に同じものを追加して素通しする（省略時は空 Map ＝ 無効）
- `algorithm.ts` は `assignCourts` が受け取っている `matchHistory` から
  `gapOf` を1回だけ組み立てて渡す（末尾から走査。O(履歴長)）
- **旧エンジン（`useObjectiveEngine: false`）は触らない**

### 3. 重み

`DEFAULT_WEIGHTS.recency` を bench で決める。制約は **`fairness`(1.5) 未満**
（超えると遅参加のキャッチアップより連続回避が勝ってしまう）。

bench で `RECENCY_WEIGHT` 環境変数からこのプロセス内だけ上書きできるようにする
（`AFFINITY_WEIGHT` と同じ仕組み）。

## 決め方（bench）

```bash
ENGINE=objective SEEDS=100 NOISE=4 CONDITIONS=21x3 ROUNDS=13 \
  RECENCY_WEIGHT=0 npx tsx scripts/bench-court-assignment.ts
# 0 / 0.2 / 0.4 / 0.6 / 0.9 / 1.2 を振る
# 採用値が決まったら SEEDS=60 以上・全条件（既定 CONDITIONS）で確認
```

**合格条件（2026-09-08 に差し替え。旧基準は下記のとおり誤りだった）**:

| 指標 | 目標 |
|---|---|
| **連投率**（空き1試合以下の割合。主指標） | **相対で 30% 以上下がる** |
| 待ちσ（出場間隔の標準偏差） | 下がる |
| 待ち（最大）/ 待ち(途中) | 悪化しない |
| 試合数幅（目的1） | +0.2 以内 |
| 占有率% / 共演（目的6） | 悪化 5% 以内 |
| 幅広% / 競り度 / 3-1%（目的3〜5） | 誤差範囲（±1pt 程度） |

**旧基準「待ち（最大）を 9.53 → 7.5 以下」は取り下げた。** 待ちの最大値は
**プール人数（21人3コートなら出場間隔の平均が 4.2 試合）とセッション末尾の裾**に
支配されていて、この項が狙う「直前に出た人を弱く嫌う」効果とは別の統計を見て
しまう（実測の内訳は下の「計測結果」を参照）。ユーザーの不満は「空き1〜2で
回り続ける人」と「11試合待つ人」の落差なので、**連投率**（回り続ける側）と
**待ちσ**（落差そのもの）を主・副の指標に据える。

なお重みの制約（`fairness`=1.5 未満）は据え置き。

**最大のリスクは目的6（多様性）の悪化**。20人3コートは待機が8人しかいないため、
直前組4人を嫌うと「残り4人」がほぼ確定してしまい、同じ顔ぶれが繰り返される
おそれがある。占有率%・共演が悪化するようなら重みを下げる。それでも両立しない
場合は採用を見送る（待ちのために多様性を売らない）。

## 計測結果

**結論: 採用見送り（`DEFAULT_WEIGHTS.recency = 0`）。**
実装・テスト・bench の口（`RECENCY_WEIGHT`）は残してあるが、**主指標「連投率が
相対で30%以上下がる」を、重みの制約（`fairness`=1.5 未満）の中では満たせなかった**
（最良で −26%）。副指標（待ちσ・待ち・試合数幅・多様性・質）はすべて条件内に
収まっていたので、**惜しいところで届かなかった**という結果。

### 0. 1回目の計測は無効（bench のセマンティクス不備）

最初に取った計測（待ちが 9.53 → 9.12 までしか動かず、8.0 で頭打ち）は
**bench 側の不備により、この項をほぼ無効化した状態で測っていた**ので破棄した。

- 本番の `matchHistory` に積まれるのは**終了した試合だけ**（`gameOperations.ts` の
  `computeFinishAndContinue` が終了時に append）。履歴の並び＝**終了順**
- 当時の bench は `assignCourts` の**直後**に `history.push()` していたため、
  **進行中の試合（＝候補ですらない人たち）が履歴の末尾 courtCount 件を占めていた**。
  `gapOf` は履歴末尾からの距離なので、候補の gap が本番より一律に押し下げられ、
  多くの候補が「値なし（＝ recency 0）」になっていた

同じシードで候補の `gapOf` を並べると差は一目瞭然（21人3C・NOISE=4・seed1）:

```
修正前  gaps=[2,2,null,null,null,null,null,2,null,null,null,null,null]   ← 3/13 人・全員 gap2
修正後  gaps=[1,1,1,1,2,0,2,null,0,2,2,0,0]                              ← 12/13 人・0/1/2 が揃う
```

そこで bench を本番に合わせて直した（`scripts/bench-court-assignment.ts`）:
進行中の試合を `pending` に持ち、次の配置を組む前に `finishedAt <= now` のものを
**finishedAt 昇順で** `history` へ移す。`gamesPlayed` / `lastPlayedAt` /
`partnerCounts` の更新は従来どおり配置時のまま（本番も配置＝出場確定なので、
ここを動かすと別物の変更になる）。**履歴の順序と中身だけ**を本番に合わせた。
この修正は `recency` だけでなく `isRecentDuplicate`（直近重複のハード制約）や
ハシゴ式（`applyStreakSwaps`）にも効く **bench 自体の忠実度の修正**であり、
既存の重み（`fairness`=1.5 等）を測り直す話ではない。

|---|---|---|---|---|---|---|---|

±0.15 / 占有率 ±0.7pt / 共演 ±0.1 の範囲で、系統的な悪化は無い。

新ベースラインの新指標（NOISE=4・SEEDS=60）。**連投率は小さいプールほど高い**:

### 4. 重みの制約（`fairness` 未満）そのものは実測では効いていない

plan の制約の根拠は「超えると遅参加のキャッチアップより連続回避が勝つ」だったが、
`LATE_JOIN=3`（練習の40%時点で3人合流・21人3C・SEEDS=100）で測ると:

| 重み | 遅参加倍率（在席比例に対する倍率。1.00 が理想） | 連投% |
|---|---|---|
| 0 | 1.19 | 6.3 |
| 1.4 | 1.18 | 5.3 |
| 2.0 | 1.18 | 4.9 |
| 3.0 | 1.18 | 4.4 |

**キャッチアップは無傷**（1.19 → 1.18）。制約を緩める余地はありそうだが、それは
この plan の設計判断（＝別途合意）なので、ここでは制約を守った結論を採る。

### 5. 採用値

**0（見送り）**。主指標に届かなかったため。実装・テスト・`RECENCY_WEIGHT` の口は
残してあるので、次のどれかを決めたら重みを変えるだけで再開できる:

- 重みの制約（`fairness`=1.5 未満）を緩める合意を取る（§4 のとおり実測では
  キャッチアップは壊れない）。ただし 30% を超えるのは 21人3コートだけ（§3）
- 主指標の閾値を「相対 30%」より緩く置き直す（1.4 で −26%、副作用ゼロ）
- 連投が多いのは**小さいプール**（13〜16人 = 連投 20〜32%）なので、そちらを
  主戦場に据えて条件と閾値を決め直す

採用値が 0 なので、**配置結果は現状と1試合も変わらない**（重み0はこの項の寄与を
0 倍するので構造的に同じ。実際に「実装あり/なし」で全条件 SEEDS=60 の出力が
完全一致することも確認済み）。

## 追記（2026-09-08 その2）: streak ベースへの作り替えと採用

上記までの gap ベース（直前の出場からの経過に応じて連続的に減点）は主指標
「連投率 −30%」に届かず一旦見送った。ユーザーからの提案を受けて実装ごと
作り替え、再計測した結果、**最終的に採用した**。

### 1. 「3連続目から嫌う」（streak ベース・allowance=2）への作り替え

指摘: 潰したいのは「1回の連投」ではなく「**連続の長さ**」だった。実データ
（`みっちゃん`: 空き `2,2,1,2,2,2` で7巡出ずっぱり／`ソンシズ`: 空き `1` の
2連続で終わる）を見ると、2連続で終わる出場は害が無い。そこで入力を
`gapOf`（直前からの経過）から `streakOf`（直近の連続出場数）に変え、
「2連続までは減点なし・3連続目から効く」（`allowance=2 / ramp=2`）にした。
主指標も「連投率」から「**3連続%**」（連続3回目以降の出場が全出場に占める
割合）に変更した。

**結果: 全条件で現状と有意差が出なかった**（21人3C: 3連続% 1.4 → 1.4、
16人2C: 1.9 → 1.9、他条件も同様）。原因は2つ:

1. **後追い**: 3連続になってから減点しても、そのときには既に3連続している。
   連続が伸びるのを止めるには、2連続目に入る判断のときに信号が要る
2. **薄まる**: この項は配置された12人（3コート）の平均。1人が満点でも
   寄与は 1/12 ≒ 0.08 で、重み1.2をかけても0.1。他の項（`variety`=2.6 等）に
   埋もれる

### 2. `allowance=0`（1回目の再出場から予防的に効く）への変更

`STREAK_ALLOWANCE` を 0 に下げ、1回の再出場（streak=1）から弱く
（`recency=0.5`）、2連続以上で満点（`recency=1.0`）に変えた。後追いではなく
**予防的**に効くため、3連続%が実際に下がった。

`ENGINE=objective NOISE=4 CONDITIONS=21x3 ROUNDS=13`（bench は上記の
finishedAt 順 flush 修正を含む）:

| allowance | 重み | 3連続% | 待ちσ | 待ち | 試合数幅 | 占有率% | 共演 | 3-1% |
|---|---|---|---|---|---|---|---|---|
| 2（旧既定） | 1.2 | 1.4 | 1.82 | 9.53 | 1.39 | 40.0 | 13.63 | 3.4 |
| **0（採用）** | 1.2 | **1.1** | 1.73 | 9.16 | 1.32 | 40.2 | 13.56 | 4.0 |

allowance=0 のほうが全指標で同等以上（3連続%・待ちσ・試合数幅が改善、
占有率/共演はほぼ同じ、3-1%のみ +0.6pt）。

### 3. 最終決定: 採用（`allowance=0` / `ramp=2` / 重み `1.2`）

主指標を「3連続%」に置き直した上で、`SEEDS=100〜300`・全条件
（13〜25人・2〜3コート）で改めて確認した結果:

**21人3コート（SEEDS=100）**:

| 重み | 3連続% | 待ちσ | 待ち | 試合数幅 | 占有率% | 共演 | 3-1% |
|---|---|---|---|---|---|---|---|
| 0（旧既定） | 1.4 | 1.85 | 9.53 | 1.43 | 39.8 | 13.64 | 3.4 |
| **1.2（採用）** | **1.1** | 1.73 | 9.16 | 1.28 | 40.7 | 13.46 | 3.6 |

**全条件（SEEDS=100、3連続% 旧既定→採用）**:
