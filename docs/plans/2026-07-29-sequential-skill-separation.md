# 2コート逐次配置の実力分離

2026-07-29

## 発端

`docs/plans/2026-07-28-two-court-skill-separation.md` で「2コート同時配置
（`assign2CourtsHolistic` → `splitBestTwoCourts`）」に上位3×下位3の同居を防ぐ
ハード制約（`hasTopBottomExtremes`）を入れた。しかし実運用では試合終了時刻が
コート間でずれるため、**両コートが同時に空く「同時配置」より、片方だけ空く
「逐次配置」（`assignCourts` 末尾の1コートずつ配置ループ → `selectBestFour`）の
方が大半**である（150シード実測: 現実的な混在パターンで同時配置率 12.8〜13.9%）。

逐次配置側の `selectBestFour` は、上位/下位の孤立を防ぐハード制約
（`hasIsolatedExtreme`）を3コート以上でしか適用しておらず、2コートでは
`getSkillGapPenalty` によるソフトペナルティのみだった。結果、13人2コートの
現実的な混在パターンで上位3×下位3 の同居が 12.2% 残っていた。

## 変更

`selectBestFour` に、2コート（`totalCourtCount === 2`）のときも
`hasTopBottomExtremes` で上位×下位の同居をハードに弾く制約を追加した。
`splitBestTwoCourts`（同時配置）と同じ判定関数を使うことで、同時配置経路と
逐次配置経路で「上位×下位を同居させない」という方針を揃えている。

### バンド幅を人数で変える（重要な調整）

当初は `splitBestTwoCourts` と同じ `EXTREME_BAND = 3`（上位3人×下位3人）で
試したが、**150シード実測で試合数幅が大きく悪化し、ユーザーが定めた許容ライン
（+0.3以内）を超えた**（詳細は下記「バンド幅の比較実験」）。

原因は同時配置と逐次配置の構造の違いにある。同時配置（`splitBestTwoCourts`）は
「8人の行き先はすでに決まっていて、2つの4人組に分けるだけ」なので、制約で
弾かれても誰も試合から漏れない。一方、逐次配置（`selectBestFour`）は
「待機中の候補プールから優先度順に1コート4人を選ぶ」経路なので、制約で組が
弾かれると**待たされている人がそのラウンドの選出から漏れる**。12人2コートは
1ラウンドの待機が4人しかなく、band=3人（上位/下位バンドで合計6人 = ロースター
の半分）だと、待っている人の半分が同居禁止の対象になってしまい、試合数の
公平性を大きく損なった。

そのため、最終的には次の可変バンド幅を採用した:

```ts
const skillGapHardBand = baseRankById && baseRankById.size <= MIN_ROSTER_FOR_SKILL_GAP
  ? SEQUENTIAL_EXTREME_BAND_MIN_ROSTER  // 1
  : SEQUENTIAL_EXTREME_BAND;            // 2
```

- ロースターがちょうど12人（`MIN_ROSTER_FOR_SKILL_GAP` の下限）: band=1
  （最上位1人×最下位1人のみハード禁止）
- ロースター13人以上: band=2（上位2人×最下位2人をハード禁止）
- `MIN_ROSTER_FOR_SKILL_GAP`（12）未満は `hasTopBottomExtremes` 内の既存ガード
  でそのまま無効

同時配置側の `splitBestTwoCourts`（band=3固定）は一切変更していない。

### フォールバック（3段構え）

ハード制約を満たす組が1つも無い場合に `candidates.slice(0, 4)` へ素朴に
落ちると、直近試合の重複回避・性別構成といった既存のハード制約まで巻き添えで
緩んでしまう。これを避けるため、`splitBestTwoCourts` と同じ考え方で
探索を二段階にした:

1. 直近試合の重複・（3コート以上のみ）上下孤立・性別構成をすべて満たし、
   かつ2コートの上位×下位同居も回避する組の中で最良（`bestCombo`）
2. 1が1つも見つからない場合、上位×下位同居の回避だけを諦めた（他の制約は
   満たす）組の中で最良（`bestBaseCombo`）
3. それも見つからない場合のみ、最終手段として優先スコア最上位4人
   （`candidates.slice(0, 4)`、従来の唯一のフォールバック）

3コート以上の挙動（`hasIsolatedExtreme` によるハード制約）は完全に不変。

## 計測方法

スクラッチパッドの `seq_holistic.ts`（イベント駆動シミュレーション、試合時間
10〜15分のばらつき、`sim`=常に同時配置 / `seq`=常に逐次配置 / `mixed`=現実的な
混在）を使用。**変更前の基準値は 98b5930 の worktree ではなく、このセッションの
実装開始時点の HEAD（f6909cd）を元にした独立コピー（アルゴリズムファイルの
みを退避したディレクトリ）に対して自分で測り直した**。人数は 12・13・14・16
（2コート×7人が主戦場、8人は稀という実運用を踏まえた範囲）。全て150シード。

3コート以上・性別なし（`focus.ts` / `reach.ts`）と男女込み（`gbench.ts`、
2コート同時配置の行を含む）は、変更前後で**完全一致**することを確認済み
（後述）。

## 未達成（正直な記録）

- **12人2コートの改善幅は小さい**（-1.4pt）。同じ理由（1ラウンドの待機が
  4人しかなく、上位/下位バンドが人数に占める割合が大きい）で band を強めると
  試合数幅の悪化が許容ラインを超えるため、これ以上は追わなかった。12人
  セッションで上位×下位の同居を根本的に減らしたいなら、試合数の公平性を
  多少犠牲にする前提の別対応（例: band=2 を許容してユーザーに周知する、など）
  が必要になる
- 13〜16人でも上位3×下位3 はゼロにはならない（2.1%〜9.8%残る）。band を
  強めれば下げられるが、試合数幅の悪化とのトレードオフになる（band=3の実測
  参照）。「試合数幅 +0.3以内」を優先する限り、この残存率が現実的な下限
- `seq` と `mixed` の改善幅に一貫した大小関係は見られない（13人は seq -4.9pt >
  mixed -3.6pt、16人は同幅 -2.2pt）。同時配置イベントの混入率の違いによる
  ばらつきの範囲とみられ、どちらかの経路が有利/不利という読み取りはできない
- パートナーの種類（味方の多様性）はわずかに減少する条件がある（13人 seq
  7.9→7.8人、16人 seq/mixed 7.3→7.2人）。誤差に近い小さな変化だが、上位×下位
  同居を避けるために組み合わせの自由度が減った副作用と考えられる
