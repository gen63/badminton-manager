# 多様性アナウンスの表示条件修正

## 背景

スクリーンショット報告: 2 コートとも使用中、待機 4 人、休憩 2 人の状態で
「💡 組み合わせの多様性を確保するため、一括配置を推奨」バナーが表示されていた。

ユーザーの指摘:
- 1 コートが終わった瞬間の待機プールは `4 (元待機) + 4 (終了直後) = 8 人`
- 8 人から 4 人を選抜できるなら多様性は十分（最適選抜なら強制再投入 0 人）
- このケースで「一括配置推奨」は不要

## 原因

`src/lib/utils.ts:155-181` の `shouldBlockForDiversity` で、空きコート 0 の場合に
`effectiveEmptyCourts = Math.max(emptyCourts, 1)` として「仮に 1 コート空いた」想定で
先読み計算していた。

そのせいで `emptyCourts=0, waiting=4` のとき
`remaining = max(0, 4 - 1×4) = 0 ≤ 2 → ブロック` となり、本来不要な場面でバナーが出る。

しかし現実には、コートが空く瞬間にその 4 人も待機側に加わるため、
プールは `waiting + 4` 人になる。先読み計算が現実の挙動と乖離していた。

## 多様性確率の整理

1 コート空き時、待機 `w` 人 + 直前対戦の 4 人 = `w+4` 人プールから 4 人選抜:

| w | プール | 最適選抜での強制再投入 | 多様性 |
|---|---|---|---|
| 0 | 4 | 4 (100%) | 0% |
| 1 | 5 | 3 (75%) | 25% |
| 2 | 6 | 2 (50%) | 50% |
| 3 | 7 | 1 (25%) | 75% |
| 4 | 8 | 0 (0%) | 100% |
| 5+ | 9+ | 0 | 100% |

→ 強制再投入 ≥ 50% (= `w ≤ 2`) のときがバナー表示の妥当な境界。
   これは現行の `baseThreshold = 2` の値と整合する。

## 変更内容

### `src/lib/utils.ts`

`shouldBlockForDiversity` から `effectiveEmptyCourts = Math.max(emptyCourts, 1)` を削除し、
純粋に `waitingCount - emptyCourts × playersPerCourt ≤ baseThreshold` で判定する。

判定式の意味が変わる:
- 空きコート 0 のとき: `waiting ≤ baseThreshold` でブロック
  - 旧: `waiting ≤ baseThreshold + 4` でブロック（先読み）
  - 新: 「次にコートが空いた瞬間の待機プールから選抜したときに、
        待機 > baseThreshold あれば十分な多様性が確保できる」という解釈
- 空きコート ≥ 1 のとき: 従来通り `waiting - emptyCourts × 4 ≤ baseThreshold`

### JSDoc / コメントの更新

- 「実際の動作範囲」コメントを新ロジックに合わせて書き直す
- 「空きコート 0 でも先読みとして表示」の説明を削除
- 多様性確率の根拠を追記

### `src/lib/utils.test.ts`

既存 15 テストの **期待値は全件変更不要**（新ロジックでも全て同じ結果）。
ただし「空きコート 0、待機 2 → 仮に 1 コート空くと余り -2 ≤ 2 → 推奨表示」
というコメントは現実と乖離しているので、新しい根拠に書き換える。

新たに以下のテストを追加:
- 空きコート 0、待機 3 → ブロックしない（ユーザー直感の境界検証）
- 空きコート 0、待機 4 → ブロックしない（スクリーンショットケース）

## 動作確認

`npm run build && npm run lint && npm run test:run` を通す。

スクリーンショット時の挙動:
- `prioritizeDiversity=true, occupiedCourts=2, emptyCourts=0, waiting=4, playersPerCourt=4`
- 新ロジック: `max(0, 4 - 0×4) = 4 > 2 → ブロックしない` → バナー非表示 ✓

過去の設計意図（2026-03-07 `block-second-court-on-low-flow`）との整合:
- 8人2コート, 1コート空き状態: `occupied=1, empty=1, waiting=4`
  → `4 - 1×4 = 0 ≤ 2 → ブロック` → 維持 ✓
