# 履歴画面: 試合ごとの分析表示（開発モード限定）

## 目的
メンバーで絞り込んだ履歴で、各試合が「格上に勝った / 取りこぼした」のどれだったかを、
チーム平均偏差値・予想勝率・判定で一目で読めるようにする。

## 表示条件
開発モード（`showPerformance`）かつ メンバー絞り込み中かつ その試合が勝敗確定済みで
推定に使われた試合（`toRatedMatches` を通った試合）。それ以外は既存表示のまま。

## 計算（src/lib/performanceRating.ts）
- 既存の Bradley-Terry のまま: P(A勝) = sigmoid(mean(θ_A) − mean(θ_B))。θ は `solveStrengths` の解を再利用し、既存結果は不変。
- `PerformanceResult.matchInsights: Map<matchId, {teamADeviation, teamBDeviation, winProbabilityA}>`。チーム平均偏差は θ の平均を既存の偏差値変換（50+10*(θ−mean)/sd、sd≈0 なら 50）に通して四捨五入。
- `judgeMatch(ownWinProbability, won)`: p≥0.65 は勝ち=順当勝ち/負け=取りこぼし、p≤0.35 は勝ち=番狂わせ勝ち/負け=順当負け、間は互角・勝ち/互角・負け。
- 閾値の根拠: 1日分（10〜15試合）の推定は誤差が大きく、60%程度の「やや有利」で負けても不思議ではない。有利/不利と言い切れる 65% / 35% を境にした。

## 表示
- 試合カードの中央列と編集/削除アイコン列の間に右寄せの分析列（2列×3行グリッドで中央3行と行揃え）: 上段チームの平均偏差 / 「vs」+下段チームの平均偏差 / 判定チップ+本人側の予想勝率。本人側チームの数字は indigo 太字。
- 成績サマリの期待勝率行の下に判定内訳チップ（0件は非表示、表示中の勝敗確定試合すべてが対象）。
- 判定チップ色: 番狂わせ=emerald / 順当勝ち=blue / 互角=gray / 取りこぼし=orange / 順当負け=淡gray。

## 追記: 全員表示時は勝者視点で 順当/互角/番狂わせ の3区分
- 開発モードでメンバー絞り込みなし（全員）のときも分析列を出す。視点は勝者チーム。
- 勝者側の予想勝率 >= 0.65 で「順当」、<= 0.35 で「番狂わせ」、間は「互角」（`judgeMatchNeutral`、閾値は既存定数を共用）。配色は本人視点の 順当勝ち/番狂わせ勝ち/互角 と同じ。
- 2行目「上段 vs 下段」はどちらも強調しない。3行目は勝者側の予想勝率。成績サマリ・内訳チップは絞り込み時のみで変更なし。

## 追記: 予想勝率を leave-one-out に変更、閾値を 60/40 に変更
- 従来の `winProbabilityA` は、その試合の結果を含めて解いた θ から計算していたため、勝者側が有利に見える後付けの値になっていた。推定に使った各試合 i について、試合 i を除いた試合で `solveStrengths` を解き直し（全体解 θ をウォームスタートの初期値にする）、その θ で試合 i の予想勝率を出す（leave-one-out）。試合 i にしか出ない選手は除外後の推定に現れないため θ=0（事前分布の平均）。
- `teamADeviation` / `teamBDeviation` は従来どおり全体推定の値（結果集計の偏差値と揃えるため）。つまり「予想勝率は LOO、平均偏差は全体推定」。判定（`judgeMatch` / `judgeMatchNeutral`）と内訳（`countVerdicts`）は `winProbabilityA` を使うので自動的に LOO ベースになる。既存の全体推定の結果は不変。
- 計算量は試合数 n に対し n 回の解き直し。ウォームスタートと配列化で対処（80 試合・16 人の合成データで約 0.7〜0.9 秒、テスト環境での計測。実際の 10〜15 試合規模ならごく短時間）。`useMemo` で結果はキャッシュされる。
- 閾値: LOO では予想勝率が 0.5 寄りになるため、互角の幅を 65/35 から 60/40 に狭めた（`FAVORED_THRESHOLD=0.60` / `UNDERDOG_THRESHOLD=0.40`）。

## 追記: カードの平均偏差も LOO に変更
- カードの平均偏差も LOO に変更（全体推定と混在すると、偏差の大小と判定が食い違うため。例: 44 vs 42 で上段が勝ったのに予想勝率39%）。物差しは全体推定の mean/sd（LOO ごとに正規化し直さない）。結果集計の個人偏差値（全体推定）とは値が異なり得る。
- 既存 LOO ループ内で θ を使い回すため計算量は増えない。不変条件: teamADeviation > teamBDeviation ⇔ winProbabilityA > 0.5（丸めで等しくなるのは可）。
