# レベル差の判定を登録レートの「数値」ベースにする（第1段）

日付: 2026-10-02 / ブランチ: `claude/rating-based-strength`（基点 82e9620 = master）

## 背景（ユーザー前提）

登録レートは割と実力通り。重要なのは (i) コート内の最大と最小が離れすぎない、(ii) チーム平均が離れすぎない、の2点。
従来は (i) soft `skillGap`（順位幅の凸形）・(ii) `competitive`（順位和の差）とも**順位**ベースで、
端の人（例: 偏差24や78）の離れ具合を過小評価していた（順位では隣と1つ差でもレートでは大きく離れうる）。

## 実装

- `pairing/strength.ts`（新）: 当日のロースター内で登録レートを z-score 標準化（±3 で丸め）し `zSpan=3.5` で割って
  「順位幅 ÷（人数−1）」とほぼ同じ 0〜1 の目盛りにする（`buildStrengthById`）。未設定レートは平均（0）扱い。
  `STRENGTH_SHAPE = { gapMix: 1, compMix: 1, zSpan: 3.5, zClamp: 3, ladder: 0 }`（書き換え可能。bench の `SGAPMIX` / `SCOMPMIX` / `SLADDER`）。
- `computeSkillGap`: コートの g を `(1-gapMix)×順位幅 + gapMix×数値幅` にして、従来と同じ凸形（knee / slope）を掛ける。
  数値幅も formRank 側と登録側を `regMix` で混ぜる。
- `computeCompetitive` と `splitCost`（チーム分け）: チーム強さ合計の差を同様に `compMix` で混ぜる。
- **順位は残す**: 順位差のハード制約（14人以上）・優先度のタイブレーク・`reachableCount` は従来どおり formRank / 登録順位。数値は soft 項のみ。
- ハシゴ式（当日の勝敗）の数値への反映は `ladder`（既定 0）。`buildFormStrengthById` は順位が動いた分（÷（人数−1））に `ladder` を掛けて強さに足す。

## ハシゴ式との兼ね合い（比較して提案）

実メンバー試算（練習1: 19人3C・練習2: 18人3C、男女比OFF、連続モード、100シード）で `ladder` を 0 / 0.25 / 0.5 / 1 に振った。
登録レート = 真の実力の前提では ladder を足すほど悪化（チーム差 2.8 → 3.1 → 4.0 → 5.7）。真の実力に偏差 σ=6 のズレを足しても
ladder>0 の利得は誤差（チーム差 5.65 → 5.54 / 5.97、練習2 は逆に悪化）。1練習 10〜12 試合ではハシゴ式の信号が弱いため。
**提案: ladder=0（数値の強さは登録レートのみ。当日の勝敗は順位ベースの経路＝ハード制約・帯の序列にだけ残す）**。つまみは残してある。
ハイブリッド（gapMix / compMix を 0.5）は両方の中間で、数値ベースだけの案に勝つ指標が無かったので不採用。

## 重みの再調整

数値ベースにするとコートごとの項が大きくなり、端の人が出られにくくなって試合数幅が広がる（待ち・連続も悪化）。
master 比で試合数幅・待ち・連続を悪化させない範囲に重みを再調整した（実メンバー試算と bench 両方で見て選択）。

| 項目 | 前 | 後 |
|---|---|---|
| `RANK_GAP_SOFT_SHAPE` knee / slope | 0.3 / 7 | 0.35 / 10 |
| `waiting` | 4.0 | 14.0 |
| `recency`（`RECENCY_WEIGHT`） | 5.0 | 9.0 |
| `AFFINITY_WEIGHT` | 2.0 | 3.0（希望ペア normal 成立率を master 水準に戻す。bench PREF_PAIRS=1/2 で master 同等以上） |

`fairness` は上げても試合数幅への効きが弱く（waiting が主レバー）、男女比 ON の 3-1% も悪化させるので 5.5 のまま。

## 結果

実メンバー（`realroster/sim.ts`、50 シード、3人一致の列は参考）。master → 第1段:

| | 練習1 | 練習2 |
|---|---|---|
| コート内偏差差の平均 | 15.9 → 15.4 | 15.9 → 15.4 |
| 差25以上の試合数 | 7.6 → 5.6 | 8.9 → 7.2 |
| 差30以上の試合数 | 2.6 → 1.8 | 2.0 → 1.7 |
| チーム平均偏差差の平均 | 5.54 → 2.75 | 5.87 → 3.29 |
| チーム差5以上 / 10以上 | 28.4→11.1 / 9.2→0.7 | 23.2→11.4 / 8.3→2.2 |
| 試合数偏り（最多−最少） | 1.14 → 1.60 | 1.30 → 1.88 |
| 2/3連続（1人あたり） | 2.25→2.17 / 0.053→0.040 | 2.29→2.32 / 0.108→0.100 |

- 最大の効果は**チーム差の半減**（competitive の数値化。試合数・連続に影響なし）。
- コート内の離れ（差25/30以上）は 2〜3割減。ただし試合数偏りが +0.5 前後に広がる（トレードオフ）。端の人（偏差24・78付近）は
  離れた相手とあたりにくくなる分、出場機会の偏りに出る。後半均等モード（60%経過後ON）では偏りの悪化が +0.2〜0.25 に収まる。
- bench（ENGINE=objective CONTINUOUS=1 GENDER_OFF=1、8x1/12x2/14x2/16x2/15x3/19x3 平均、NOISE=2/4、SEEDS=200 ROUNDS=20）。
  bench の登録レートは等間隔（外れ値なし）なので順位ベースと差が出にくい。master → 第1段:
  幅広% 18.2→18.4、登録上下% 24.7→23.9、競り度（チーム差）24.6→18.2、試合数幅 1.49→1.21、待ち 5.75→5.46、2連続% 21.1→19.2、
  3連続% 2.13→2.25、4連続+% 0.31→0.39。悪化: 同4人% 1.15→2.01（15人3Cで 4.8→6.8）。

## 副作用・テスト

- 既存テストのうち、`waiting` / `recency` の既定値に依存する5本は、既定値を上げた意図に合わせて直した（アサーションは緩めていない）:
  `objective.test.ts` の recency 実効コスト（重み 9）、`assignRound.test.ts` の後半均等化・2連続目、`algorithm.test.ts` の「同優先度で 2M2F」
  は検証したい関係（窓の広さ・性別 vs 優先度）を保つため `waiting: 4.0` に固定。
- 新規: `strength.test.ts`（標準化・外れ値・未設定・ladder・数値 skillGap / competitive・チーム分け）。
- 男女比 ON（bench GENDER_OFF なし）の 3-1% は 9.6 → 15.6。ON は運用の主でないため許容（plan 追記で再確認）。

## 却下・保留

- 順位ハード制約の数値化: 安全網として残す方針のため見送り。
- 同順位タイの優先度を同率にする案（待ちの重みを上げても性別が負けない）: 序盤の選出が崩れて試合数幅が 2.3〜3.9 に悪化したので不採用。
