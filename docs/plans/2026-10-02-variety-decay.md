# 同じ顔ぶれの繰り返し回避の作り直し（B3 撤去 + variety の減衰化）

日付: 2026-10-02 / ブランチ: `claude/variety-decay`（試作・計測。本番反映は未実施）

## 背景・方針（ユーザー）

- ハード制約 B3「直近重複」（`hasSimilarRecentMatch`: 各人の直近3試合と3人以上重複で違反）を**外す**。
- 代わりに点数ルール（目的6 variety）を改善する。
  - 同じ2人の共演が重なるほど、ペナルティを徐々に強く（2回目は許容、3回目以降は強く）。
  - 過去の共演は遠いほど弱く（減衰）。4〜5試合前に手動交換等で偶然同コートだった場合も、直近3試合の窓の外でも効くように。
  - 同じ4人（チーム分けを変えても同じ顔ぶれ）は、ペア単位より強めでもよい。
- **優先順位: 1. レベル差の大きい試合の抑制 > 2. 連続回避 > 3. 男女**。繰り返し回避を強めても強さが悪化しないことが絶対条件。

## 設計案

| 案 | 内容 |
|---|---|
| A. B3 外しのみ | variety は従来のまま（その日の累計回数・減衰なし・4回で頭打ち） |
| B. 試合数減衰 | ペアごとに Σ decay^(経過試合数) の重み付き共演回数 → 凸関数で加算。経過試合数 =「その試合の後、2人が平均で何試合したか」 |
| C. 時間減衰 | 同様だが、重み = 0.5^(経過分 / 半減期)。経過 = 履歴内の最新終了時刻 − その試合の開始時刻 |
| D. 4人顔ぶれ項（B/C に追加） | 同じ4人（チーム分け不問）の減衰重み和を別枠で加算 |

どれも `Date.now()` 非依存（履歴内の値のみ）。実装は `src/lib/pairing/repeatDecay.ts`（`buildRepeatWeights`）。

### 時間減衰 vs 試合数減衰（推奨: 試合数減衰）

- 試合数減衰は「その人たちがその後に何試合したか」で薄まる。休んでいた人は記憶が薄まらず（また同じ人たちと、という体感に沿う）、コートの回転速度（1試合6〜9分、コート数）に依存しない。人数・コート数が違っても同じ減衰率で使える。
- 時間減衰はコートの回転が遅いと薄まり方が速すぎ/遅すぎになり、半減期を条件ごとに調整する必要がある。bench でも強さは同等（幅広%・極端%）で、繰り返し抑制（同4人%）は試合数減衰より弱かった（20分半減: 6.1% / 40分半減: 4.3%、試合数減衰: 3.6%）。
- 結論: **試合数減衰を採用**（時間減衰のコードは残していない）。

## 採用した形（案 B + D）

variety（目的6、重み 2.6 据え置き）の各コートの項:

```
w_ij  = Σ decay^((その後のi の試合数 + その後のj の試合数)/2)   … 共演（味方+敵）の減衰重み和
        + 0.2 × その日の累計共演回数                              … 減衰しない底上げ
x     = Σ_{6ペア} (w_ij / scaleOf_ij)^2.5                         … 凸（1回目は軽く、重なるほど急に）
項    = min(1, x / 6) + 0.5 × min(2, 同じ4人の減衰重み和)         … 4人項は別枠で加算
```

`scaleOf`（序列の端の人の補正）は従来どおり。`decay = 0.85`。例: 4〜5試合前の共演は重み 0.85^4.5 ≈ 0.48 でそれなりに効く。直近3試合の窓の外でも効く。
B3 撤去に伴い `assignRound.ts` の `isRecentDuplicate`（評価の違反・初期解・直近重複修復）、`algorithm.ts` の小プール緩和（`SMALL_POOL_MAX_SURPLUS` 等）を削除。`hasSimilarRecentMatch` は旧エンジン（`useObjectiveEngine: false`）用に残す。

### 探索で分かったこと（根拠）

- **B3 外しだけ**では強さ系は微改善（幅広 25.1→24.0 等）だが、同4人が 5.4%→10.6% に倍増する。B3 は「同じ4人」の再演を実際に抑えていた。
- 減衰 variety の重みを上げて繰り返しを減らすと**必ず強さが悪化**する（例: variety 重み 8・scale 2 で 幅広 +2pt、3-1 +1.6pt。重み 5〜10 でも同傾向）。skillGap を 2.5〜5 に上げて相殺すると 3-1 と 2連続が悪化（強さ優先のため不採用）。gender を 2.4 に上げると 3-1 は下がるが 3連続 が 2.5→2.95 に悪化（連続 > 男女の優先に反する）ので不採用。
- 4人項を ペア項と同じ飽和式に混ぜると効きが弱く（同4人% 10→7）、**別枠で加算**（0.5 × 重み和、上限2）にすると 3.5% まで下がった（強さ影響なし）。同じ4人はまれなイベントなので強く罰しても強さへの影響が小さい。
- ペア項の飽和を x/(x+2)（凹）にすると「3回目以降は強く」にならない（増分 0.33→0.33→0.15）。min(1, x/6) + 指数2.5 にして凸にした。同2人3+% が 71.6→68.4、19人3C では 66.3→60.0。
- 1人あたり直近の再会数（再会3）はどの構成でも ~2.4〜3.2/6組でランダム期待値と同程度。**メンバー構造上避けられない繰り返し**（帯を保つ制約）が大半で、点数ルールで動かせるのは同2人3+% と同4人%。
- decay 0.7/0.8/0.85/0.9 の差は小さい（0.85 を採用）。底上げ（rawFloor）0.1〜0.4 も差は小さい。

## 懸念・未決事項

- 2連続% が 22.87→23.17（+0.3pt）。SEEDS=200 の標準誤差程度だが、「soft 飽和」版（22.75）の方が良かった。ペア項の凸化とのトレードオフ。
- 同2人4+%（累計4回以上）は 48.9→52.5% と悪化。減衰により「その日の累計」より「最近」を重視する設計の帰結（従来 variety は累計4回で頭打ちの強い罰）。累計も強く見たいなら `rawFloor` を上げるが、試行（0.3〜0.4）では改善しなかった。
- 15人3C で同4人% が 7.3→9.2 に悪化（B3 なしで3コートの組合せが固定化しやすい構成）。8人1C は極端% 18.7→19.5。
- NOISE=0/8、遅参加、ペア希望ありの条件は未計測。
