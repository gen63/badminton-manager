## Context

練習をスムーズに回すため、「次の試合に入る可能性が高いメンバー」を事前に見せて
準備（ラケット・ドリンク・コート脇への移動）を促したい、という要望。

配置アルゴリズム `assignCourts` は与えられた状態に対して**決定的**なので、
「次に配置が走るときの状態」を先読みして同じ関数を空打ちすれば、次の試合の
メンバーを事前に算出できる。真実のソースは変えず、読み取り専用の予測として
UI に出す。

## 予測の作り方

| 状況 | 次に配置が走るタイミング | シナリオ |
|---|---|---|
| 空きコートがある | 「自動配置」ボタン（`handleAutoAssign`） | 現在の待機者で `assignCourts` を1回。結果は確定 |
| 全コート稼働中 | どれかのコートが終わったとき（連続モードなら `computeFinishAndContinue`、OFF なら手動の自動配置。どちらも同じ `assignCourts` を呼ぶ） | **プレイ中の各コートが終わったケースを全部**シミュレート |

シナリオごとの選出結果を集計し、**出現率**（選ばれたシナリオ数 ÷ 全シナリオ数）で
ランク付けする。試合終了のシミュレーションは `computeFinishAndContinue` の
「試合記録の追加 / gamesPlayed +1・lastPlayedAt 更新・試合後の休憩判定 /
コートのクリア」をそのまま再現する（書き込みはしない）。

## 「確定4人」は原理的に出せない（実測）

実アルゴリズムを叩いた計測（各200試行、ランダムなレート・性別・試合数・履歴）:

```
3コート稼働 / 待機10人: 確定0人=6%  1人=22% 2人=34% 3人=19% 4人=20%
2コート稼働 / 待機10人: 確定0人=4%  1人=14% 2人=30% 3人=28% 4人=25%
3コート稼働 / 待機6人 : 確定0人=8%  1人=28% 2人=45% 3人=15% 4人=5%
```

全シナリオ共通（出現率100%）で残るのは3コートで平均2人程度。「次の4人」を
言い切ることはできないので、**2段階（ほぼ確定 / 候補）で見せる**。

### どのコートが終わるかで1〜1.5人変わる（が、実力帯は変わらない）

序列順にコートを埋めた状態（コート1=上位、コート3=下位）で、上位コート終了と
下位コート終了の選出を比較した計測:

```
3コート / 待機10人: 一致人数=2.77/4 (完全一致=38%) | 選出者の平均レート 上位終了=1355 / 下位終了=1356
3コート / 待機6人 : 一致人数=2.50/4 (完全一致=20%) | 選出者の平均レート 上位終了=1288 / 下位終了=1304
2コート / 待機10人: 一致人数=2.75/4 (完全一致=39%) | 選出者の平均レート 上位終了=1397 / 下位終了=1401
```

メンバーは1〜1.5人変わるが、**選出者の実力帯は変わらない**。1コート分の配置では
実力帯を決めるのは court id ではなく `selectMostUrgentGroup`（最も待たされている
グループ）であり、「上位コートが空いたから上位の人が入る」という挙動にはならない。
変動の要因は、終わった4人が待機に戻ることでグループの緊急度・試合数バランス・
ペア履歴が動くこと。

（注: `assignCourts` の doc コメントに残る「固定コート配置 upper→C1」は現在の
実装と食い違う古い記述。今回は触っていない）

## 確定仕様

### 判定ロジック（`src/lib/nextMatchPrediction.ts`）

| 項目 | 仕様 |
|---|---|
| `predictNextMatchPlayers(players, courts, matchHistory, reservations, options)` | 予測結果を返す純粋関数。書き込み・ストア依存なし |
| ほぼ確定 (`certainIds`) | 出現率 100%（どのコートが終わっても選ばれる） |
| 候補 (`likelyIds`) | 出現率 `LIKELY_THRESHOLD`(=0.5) 以上。ただし**次の試合の定員**（ダブルス4人 / シングルス2人）に届くまでは出現率の高い順に補充する（同率は打ち切らない） |
| `appearanceRate` | メンバー ID → 出現率。UI の並び順に使う |
| `scenarios` | シナリオ別の内訳（どのコートが終わったら誰が入るか） |
| 配置不能 | `assignCourts` の例外は握りつぶし、そのシナリオを捨てる。全滅なら空の予測 |
| 準備中コート（配置済み・未開始） | 終わらないのでシナリオ対象外 |

`assignCourts` に渡すオプションは `handleAutoAssign` / `computeFinishAndContinue`
と同じ組み合わせに揃える（ズレると予測と実配置が食い違う）。

### 表示（`src/components/NextMatchPredictionBar.tsx` + `MainPage`）

- 配置: **「待機中 (N)」見出しの直下**、待機カードグリッドの上に横1行の帯
- 帯: ほぼ確定 = indigo 塗りチップ / 候補 = indigo 枠線チップ（出現率の高い順）
- 待機カード: ほぼ確定 = `border-indigo-400 bg-indigo-50/60` + 「次」バッジ、
  候補 = `border-indigo-200` + 「候補」バッジ（バッジは右上、予約バッジは左上のまま）
- 優先順位: 選択中 > ほぼ確定 > 候補 > 予約（予約は左上バッジで判別可能）
- 「※現在の状況からの予測です」を常時表示。予測が空なら帯ごと非表示
- 表示対象は全員（管理者限定・dev 限定にはしない）
