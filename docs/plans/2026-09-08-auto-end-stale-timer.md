# 押していないのに全コートが終了する / ありえない試合時間が残る

2026-09-08

## 症状

- 誰も「終了」を押していないのに、**全コートの試合がまとめて終了**していることがある。
- 試合履歴に **そんなに長くやっているはずのない試合時間**（24〜27 分）が残る。
  実測の試合時間は中央値 6.5 分・p90 8.0 分なので明らかにおかしい。

実データ（2026-09-08 ぴいす）: 24 試合中 3 試合が連続して 27 分 / 25 分 / 24 分。
3 面運用なので **3 コートが同時刻に終了した** ことを示している。

## 原因

自動開始（`MATCH_AUTO_START_MS` = 3 分）と自動終了（`MATCH_AUTO_END_MS` = 15 分）は
`MainPage` の `setTimeout` で発火する。どちらも遅延を

```ts
Math.max(0, 期限 - Date.now())
```

で計算しているため、**期限をすでに過ぎている場合は「即発火」する**。
そして期限を過ぎているのに未発火ということは、そのあいだ **アプリが動いていなかった**
（画面ロック・バックグラウンドでのサスペンド・タブ破棄・アプリ再訪）ことを意味する。

つまり「アプリが止まっていた時間」までも試合の経過時間として数え、復帰した瞬間に

1. 準備中コートを `startedAt = assignedAt`（＝はるか昔）で自動開始する
2. その直後、`startedAt + 15 分` をとっくに過ぎているので自動終了が即発火する
3. プレイ中コートも同様に、全コート分の自動終了がいっせいに走る

が起きる。結果:

- 誰も押していないのに全コートが終了する（＝症状 1）
- `finishedAt = 復帰した時刻` なので、実際は 7 分程度で終わっていた試合が
  24〜27 分として履歴に残る（＝症状 2）。この値は `sheetsApi` の「試合時間」として
  badminton-rating のスプレッドシートにもそのまま流れる

手動「開始」も同じ穴を持つ。`computeStartGame` は `assignedAt` をそのまま `startedAt`
にするため、アプリが止まっていた間に古くなった配置から「開始」を押すと、押した瞬間に
すでに 15 分超過扱いになる（`FinishGameButton` の誤タップロックが `startPressedAt` を
使っているのと同じ問題が、経過時間側に残っていた）。

## 方針

> **自動処理は「アプリが起きていて観測できていた時間」だけを根拠にする。**
> 止まっていた間に過ぎた期限は、実際に何が起きたか分からないので自動では動かさない。

タイマーが予定どおり発火したかは **発火の遅れ** で判定できる。動いているアプリの
`setTimeout` は（バックグラウンドスロットリングを含めても）せいぜい 1 分程度しか
遅れない。それを大きく超えていれば、アプリは止まっていたと判断してよい。

## 設計

### 1. `AUTO_TIMER_MAX_LATENESS_MS`（2 分）を追加（`gameOperations.ts`）

自動開始・自動終了のタイマーが「予定どおり発火した」とみなす遅れの上限。
Chrome はバックグラウンドタブのタイマーを 1 分に 1 回程度へ絞るので、その倍を取る。

### 2. 自動終了: 遅れて発火したら終了しない

- 純粋関数 `isAutoEndDue(startedAt, now)` を追加。
  `now` が `startedAt + MATCH_AUTO_END_MS` を過ぎており、かつ遅れが
  `AUTO_TIMER_MAX_LATENESS_MS` 以内のときだけ true。
- `FinishGameOptions` に `autoEnd?: boolean` を追加し、`finishMatchAndContinue` の
  transaction 内（＝リモートの `startedAt` に対して）で判定する。条件を満たさなければ
  **書き込まずに** `result: 'stale_auto_end'` を返す。判定を transaction 側に置くことで、
  どの端末・どのバージョンから呼ばれても同じ不変条件が効く。手動終了は従来どおり無条件。
- `MainPage` はローカルの `courts` を見た時点でも同じ判定をして、遅れているコートには
  そもそも transaction を投げない（判定の最終権限は transaction 側に残す）。
- 自動終了を見送ったコートは、**管理者にだけ** コートごとに 1 度だけ
  「長時間続いています。終わっていれば終了を押してください」と案内する。
  自動で消す代わりに、人に気づかせて手動終了に寄せる（終了操作の権限が無い人に
  促しても動けない）。長引いているコートはコート枠の点滅・待機ガイドでも
  既に強調されている。

### 3. 自動開始: 遅れて発火したら開始しない

`computeAutoStartGame` は `assignedAt` が `MATCH_AUTO_START_MS + AUTO_TIMER_MAX_LATENESS_MS`
より古ければ `null`（＝書き込みなし）を返す。準備中のまま人の「開始」に委ねる。
古い配置を昔の時刻で開始してしまうと、その場で自動終了が走って幻の試合が記録される。

### 4. 手動「開始」: 古い配置は `now` を開始時刻にする

`computeStartGame` は `assignedAt` が上記の上限より古いときは `now` を `startedAt` に
する。「準備中の時間も試合時間に含める」という元の意図は、自動開始が保証する
3 分の窓の中でだけ成り立つため、その窓を超えた配置は起点として使わない。

## スコープ外

- 15 分という閾値そのものの見直し・設定 UI 化。
- 既に履歴に入ってしまった不正な試合時間の補正（履歴編集で対応）。
